# 长廊 Corridor · 艺术新标签页

<sub>v1.21.0</sub>

把每一个新标签页变成一面美术馆的墙。106 幅公有领域杰作（默认展出 93 幅），双语策展导览，
五种呈现模式，可自动或手动换画，图片抓取后存入本地、离线可用，每天还会自己再添几幅。
接上你自己的模型之后，界面与作品信息可以换成**世界上任意两种语言** —— 一种母语，一种外语。

---

## 一、安装

### 从 Chrome 网上应用店（推荐）

**[▸ 长廊 Corridor · 艺术新标签页](https://chromewebstore.google.com/detail/mnllopjjkbkoeljonbgmlabijamcjlam)** —— 装完打开一个新标签页即可，之后会自动更新。

### 开发者模式加载（想改源码时用）

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择 `corridor-newtab/` 文件夹（即包含 `manifest.json` 的这一层）
5. 打开一个新标签页即可

> 首次安装会自动打开一个新标签页。若新标签页没有变化，检查是否有其他扩展也在接管新标签页。
> Edge / Brave / Arc 等 Chromium 内核浏览器同样适用。

卸载或停用：回到 `chrome://extensions/` 关闭或移除即可，本地缓存会随扩展一并清除。

## 二、界面与操作

### 五种呈现模式（右上角第一个按钮循环，或按 `M`）

| 模式 | 说明 |
|---|---|
| **美术馆展墙** | 模拟真实展厅：墙色与材质、顶部射灯、十种画框、亚麻内衬或卡纸留白、落墙投影、右下角墙签。**墙签上永远排着两行标题**：上面是当前界面语言的名字，下面小一号是另一种语言的原名——真展签就是这么做的。 |
| **环形长廊** | Cover-flow 式 3D 旋转画廊：中心一幅正对你，两侧依次侧转、变暗、失焦。**默认每 4.2 秒转到下一幅**（可调）；也可以**按住鼠标左右拖动**（带甩动惯性，松手自动吸附到最近一幅），或用 `← →`、滚轮。点中心放大。整条队列用浮点位移驱动，每转一格只回收落到最外侧的那一张，其余六张的图片不重载，所以滚动时不闪不抖。 |
| **胶卷** | **一幅焦点图**：正中那一幅完全平整、正对着你、最大也最亮（片门平顶只罩住它一幅，片基脚下垫着一圈放映机光池）。两侧是一条**蜿蜒过来又远去的平滑长带**：出了片门，画格以长过渡（2.1 格高）单程拧向侧后方（渐近 46°），两翼轻轻抬起成一道浅谷，画格依次转侧、缩小、变暗、变虚，最后在屏幕两端缩进放映室的暗处——转角逐格渐变（相邻 ≤16°），**屏内能同时看到约 8–9 幅的全貌**（画格高占窗高 26%、封顶 300px）。片基亮黑光泽，远处画格按距离挂离散模糊档（0.5 / 0.9 / 1.3px）。五种片型，节拍可调（逐格 / 连续）。拖动手动卷片，`← →`、滚轮翻格，点片门那格放大。 |
| **沉浸式** | 作品铺满整屏。横幅比例接近屏幕时铺满；竖幅、超宽幅自动改为「完整显示」，背后垫一层同一幅画的柔焦放大。 |
| **瀑布流** | 整墙作品按列缓慢向上流动，各列速度略有差异形成层次；悬停某幅即暂停并浮出信息，点击直接进入沉浸式。滚轮可手动翻。 |

**任何模式下，鼠标移到画上都变成放大镜，点一下就能看细节** —— 展墙、环形长廊、胶卷、沉浸式都一样。
（环形长廊与胶卷里为了拖拽设了指针捕获，浏览器会把 click 事件改派给整个舞台，
所以这两处的点击是按坐标命中判定的，不是挂在每一格上的 onclick。）

后两种模式里画框设置同样生效——你在展墙里挑好的框，走廊和长廊里挂的就是那一款。

> **环形长廊的展签**（v1.7 改版）：不再套用沉浸式那张浮在角落的信息卡，
> 而是像真展厅一样，把**说明牌直接放在当前这幅作品的正下方**——
> 一道发丝短线、流派与年代、标题（另一种语言的标题以斜体附在下面）、作者、收藏地，最后是一句导览。
> 牌子的位置按当前那幅画的实际下沿算出来，所以竖幅和横幅切换时它会跟着上下移动，始终贴着画走。
> 同时中心那幅**放大到 1.22 倍**并略微提亮提彩，打了一道顶光、边框加深、镶一道极细的暖色内圈；
> 两侧的作品退得更远、依次压暗去饱和失焦，左右两端还有一层渐隐——注意力自然落在中间那一幅上。
>
> **展签的换字跟着画走**（v1.7.1）：之前它要等缓动收敛才换，而 tau=240 的指数缓动要 ~1.3 秒才落到阈值内，
> 所以画早就停稳了、字才姗姗来迟。现在改成看**离最近一格还有多远**：画一动字就随它退场，
> 越过半格立刻把内容换好（此时还是隐形的），等画滑到最后一点点再逐行浮起来。
> （另外那段淡出本来就没生效过——`#carousel.lit .ccap` 的权重压过了 `.ccap.swap`，字是硬切的。）

### 十种画框（离线光照渲染，参照实物线脚）

画框不是 CSS 描边。每种线脚先按真实剖面建高度场——**外唇 → 凹槽 → 珠圆 → 内缘线脚**，
分段保留锐利转折（真框的 arris 是硬的，不是糊的）——再叠上浮雕纹样，解出法线，
用 Lambert 漫反射 + Blinn-Phong 高光 + **光线步进投影** + 环境光遮蔽照亮（光从上方偏左，与展厅射灯一致）。

上色区分**水金与油金**：平滑顶面是水金打磨过的，高光锐利偏冷；雕花处是油金，哑光偏暖；
高点磨损露出红色**底胶**，凹处积着赭褐色的做旧，表面有细龟裂。
输出成 9 宫格贴图，用 `border-image ... round` 铺开，四角自动 45° 斜接。

| 风格 | 线脚与纹样 | 默认留白 |
|---|---|---|
| **月桂描金** | 外缘月桂叶带 + 浆果，宽凹面，内缘串珠 | 亚麻内衬 |
| **沙龙金** | 外缘齿饰，大面积水金凹面，内缘卵箭饰 | 亚麻内衬 |
| **巴洛克金** | 最宽，厚重茛苕卷叶，深度做旧 | 无（直接入裁口） |
| **洛可可蓝金** | 藏青漆身 + 描金贝饰 + 四角花饰 | 无 |
| **乌木金线** | 黑漆阶梯剖面 + 贴金内缘线 | 卡纸 |
| **胡桃木** | S 形线脚，年轮顺着框走 | 卡纸 |
| **白橡** | 擦白橡木，开放棕眼 | 卡纸 |
| **极简黑框** | 哑黑盒形剖面 | 大留白 |
| **细金框** | 极细暖金 | 大留白 |
| **画布浮框** | 深色托盘框，与画布之间留悬浮缝隙 | 无 |
| **无框** | 只有画布与落墙投影 | 无 |

### 画与框之间的留白

这一项决定了「专业感」。规矩来自真实的装裱惯例：

- **油画进金框不加卡纸**——画布直接落进裁口，中间最多垫一道**亚麻内衬**（linen liner），
  也就是包着亚麻布的窄平面，内缘再压一道金线。月桂描金和沙龙金默认就是这样。
- **纸本作品才用卡纸**（mount）——白卡纸开窗，窗口是 45° 斜切的，露出白色纸芯。
  极简黑框和细金框默认给**大留白**，就是上传参考里那种「画很小、白边很宽」的当代装裱。
- 卡纸窗口的斜面、卡纸投在画面上的一道暗影、画布本身的一圈暗边，都做了。

设置里「留白方式」可以手动改成：随画框 / 亚麻内衬 / 卡纸 / 大留白 / 无。

另有一条独立的**「留白宽度」滑块**（0.40× – 2.00×），在当前留白方式的基础上整体加宽或收窄，
拖动时画面实时跟着变。喜欢当代美术馆那种「画小、白边极宽」的挂法，把它拉到 1.6× 以上就对了。

### 墙面颜色与纹理

十种展厅漆色：炭黑、石墨灰、鸽灰、暖灰、石膏米、展厅白、美术馆绿、勃艮第红、普鲁士蓝、陶土红。

**二十五种墙面材质**，v1.5 按真实展墙的做法重建。

先说清楚现实里的展墙是怎么做的：美术馆的墙通常是 **半英寸胶合板打底 + 石膏板**（胶合板是为了随处能吃钉挂画），
接缝填缝后**整面满批一道**——也就是 **Level 5 级** 的做法，只有满批过的墙，在擦地射灯那种掠射光下才不会把接缝照出来；
面漆是哑光乳胶，一年换展要重刷两三次，所以墙上会积起一层薄薄的漆膜、留下补过的钉眼和滚筒搭接。
所以真正的「美术馆展墙」不是拉毛、不是艺术漆，而是**近乎平整、但在斜光下仍有极细起伏的哑光白**。

历史宅邸类博物馆是另一路：伊莎贝拉·嘉纳博物馆的展厅至今用织物包墙，
**锦缎光滑所以反光、丝绒吸光、花缎表面不平所以散光**——同一间屋子里靠三种织法调节光线。
二十世纪的现代美术馆则流行**麻布包板**。数字与沉浸展厅又是另一套：声学毡、消光黑箱、LED 屏、微孔吸音板、投影幕。

材质全部是按高度场解法线再打光渲出来的浮雕，用 FFT 做严格周期的带限噪声保证接缝隐形；
渲完再把亮度做**标准差归一化**到各自的目标反差（五级批白 σ=0.009，清水混凝土 σ=0.033），细腻而不失真。

**v1.7 把「展墙做法」与「石材与硬装」这两组整个重做了一遍**，起因是它们看着糊。查下来是三件事叠在一起：

1. **贴图 512px 却要放大到 640–820px 显示**——先天就被拉虚。现在这两组渲到 **1024px，显示尺寸一律小于它**，永远是降采样。
2. **划痕的角度参数写了却没用上**，所以「交叉打磨痕」根本没交叉，威尼斯灰泥的抹痕成了一排横条纹。
   现在改用频域的方向性滤波，角度真的生效，而且仍然无缝。
3. **带限噪声把频谱切成了方块**，方块频谱的自相关是 sinc，会在墙上留下淡淡的斜向波纹（微水泥上最明显）。改成平滑的径向截止。

另外补上了真正近看才有的东西：混凝土的**气泡孔**与对拉螺栓孔、木材的**管孔**与髓射线、洞石沿层理聚集的孔洞、
砖墙**每块砖各自不同的颜色**、砂岩的沉积色带。木纹、砖色、混凝土色斑这类**本身就是颜色深浅、光打不出来**的特征，
单独走一条反照率通道叠进去。

最细的那层漆膜颗粒**单独拆成一张共享贴图**（`grain.webp`，256px，固定 128px 平铺）：
纯噪声没有地标，小图重复看不出来，却让每种墙面都有 1–2px 的细颗粒；
而 14 张结构贴图不必再背负不可压缩的白噪声，体积从 ~3.5 MB 降到 ~1.1 MB。
选材质的色块也叠了同一层颗粒，所见即所得。

| 分组 | 材质 |
|---|---|
| **展墙做法** | 五级批白（满批一道，只剩极淡的批刀起伏与砂痕）· 哑光滚涂（滚筒橘皮 + 补过的钉眼 + 搭接）· 批刀刮痕 · 威尼斯灰泥 · 抛光灰泥 Marmorino · 刀抹拉毛 · 微水泥 · 硅藻泥 · 蛋壳漆 |
| **织物包墙** | 麻布包板 · 亚麻墙布 · 真丝壁布 · 丝绒 · **锦缎**（地与花同色，靠经纬方向相反的缎纹反光成像）· **花缎**（花头鼓起，表面不平所以散光） |
| **数字展厅** | 声学毡 · 消光黑箱 · LED 屏（细间距像素阵列）· 微孔吸音板 · 投影幕 |
| **石材与硬装** | 清水混凝土（模板缝 + 对拉螺栓孔 + 骨料）· 木饰面 · 洞石 · 砖墙 · 砂岩 |

> 深色墙上 overlay 的相对调制是 2·b·s，和浅色墙完全不是一个量级：
> **结构纹要提反差才看得见，颗粒反而要压下去，否则就成了雪花**。
> 所以深色墙下纹理按自身反差分三档提（最平的五级批白 / 蛋壳漆 / 哑光滚涂提 3.6 倍，
> 拉毛、混凝土、砖、砂岩这些本来反差就大的只提 2.0 倍），颗粒层统一降到 42%。
> 这样丝绒挂在美术馆绿上、锦缎挂在勃艮第红上才看得出织法。

选浅色墙时界面会自动切成深色图标与深色文字。

### 墙签会翻面

展墙模式右下角那张墙签**宽度跟着内容走** —— 长的自然宽些、短的自然窄些，
常规作品每一行都排得下；真遇上六十多字符的超长标题才会换行。
墙签在版面里占的是一格**恒定宽度**的位置，自己贴着这一格的左边按内容向右伸缩，
所以换作品、翻语言时**左边那幅画一动不动**，墙签的左端离画框也永远是同一个距离。

墙签**点一下就像闪卡一样翻到另一种语言**（绕竖轴转半圈，转到侧面那一瞬换内容）——
正面是**母语**，背面是**外语**，作品名、艺术家、材质、收藏机构一起翻。再点一下翻回来。
翻过面的那张右上角有个小圆点，免得看不出来。

默认这两面就是中文和英文。换成别的语言之后（见「五之三、说你的话」），
这张墙签就成了一张**语言闪卡** —— 正面「星月夜」，背面 *La Nuit étoilée*。
某一幅还没译到外语时，背面会退回英文，绝不会两面一模一样。

## 三、设置项

设置抽屉分**五页**：呈现 / 展厅 / 轮换 / 图库 / 存储。每一页由若干**分组**构成，
**点分组标题就能收起来**，标题右侧显示当前值（收着也知道设成了什么），
开关类分组（每日新作、自定义图库、AI 补全）的总开关直接放在标题行上。
标题栏右边一排是 **太阳 / 月亮 · 当前 / 全部 · 重置 · 关闭**，四个控件同高同圆角同字号。
「当前」（默认）只列出当前这种呈现模式用得上的设置 —— 看展墙时不会看到胶卷片基和走带方式，

## 四、藏品数量与每日新作

内置 **106 幅**精选作品，默认展出 **93 幅**——**办公模式是默认开着的**，它会把 13 幅含裸体的作品排除在轮换之外
（`106 − 13 = 93`）。这 13 幅在藏品库里仍然看得到，也点得开，只是不会自己轮到你屏幕上。
想全部参与轮换，关掉「设置 → 轮换 → 办公模式」即可。

从 v1.5 起，藏品库还会**自己长**：

- 每天一次，扩展会从 Wikimedia Commons 的策展分类（精选图片、优质图片、各大馆的绘画分类、名家分类）
  里再挑 **3 幅**公有领域作品补进来，最多留 150 幅，满了删最早的。
- 抓取是**广度优先地在分类树里走**，走到哪里记在本地，第二天接着走——所以每天看到的都是新的一段，
  今天走到北斋，明天可能就到莫里索、弗里德里希。
- 只读 Commons 的公开 API，不需要账号，不上传任何东西。抓下来后在本地算出主色色卡与占位图，
  和内置作品用同一套呈现。
- 筛掉的东西：非公有领域、宽度不足 1400px、比例太极端、文件名里带 detail / verso / x-ray 之类的局部与技术照、
  维基用户自己拍的现场照（Credit 是 Own work）、新闻社照片。
- 这些作品在藏品库里有**单独一页「每日新作」**，卡片上会注明元数据来自 Commons、没有本项目撰写的导览——
  内置的 106 幅才是逐幅写过导览的。
- **入口在顶栏**：一枚画夹图标，有没看过的新作时会安静地呼吸一圈金边并点一颗小点。点开是「今日画夹」——
  几张画像刚从画夹里抽出来，依次落到台面上，带一点随机的倾斜和投影。点任意一张直接进展墙看大图。
- **中英双语怎么解决的**：Commons 的结构化数据里有「这张图是哪件作品」（P6243）和作者（P170），
  顺着它们到 Wikidata 取中英文标签。**作者名基本都能拿到中文**（如 Katsushika Hokusai → 葛饰北斋），
  收藏机构、材质同理；作品标题则看 Wikidata 上有没有中文名，没有就沿用原名并在详情里注明。
  一次更新只发三个只读请求。
- **满 150 幅之后**：**收藏过的一律留着**，其余按加入时间从最早的开始退场，腾出位置给新来的。
  所以想长期留住某一幅，收藏它就行。
- 不想要就关掉：设置 → 缓存 → 每日新作。旁边还有「立即更新」和「清空每日新作」。

## 五、自定义图库（把你自己的图片挂进来）

设置 → 图库 → **自定义图库**。可以加**好几个来源**，两种：

| | |
|---|---|
| **＋ 文件夹** | 本机目录。用浏览器的 File System Access API，目录句柄存在本地，下次打开新标签页直接复用；Chrome 偶尔会要求再确认一次读取权限，卡片上会提示。**图片始终留在你自己的硬盘上** —— 扩展不复制、不上传、不进缓存库，只在显示那一刻读一次。 |
| **＋ 网址** | 一个在线图库。目录索引页、普通图库页面、一份 JSON 清单、一行一个网址的纯文本，或者干脆就是一张图 —— 都认。第一次扫会问你要那个域名的访问权限；抓回来的图走正常缓存那条路，离线照样看得到。 |

一个来源一张卡：图标分文件夹 / 网址，右边写着它收了多少张。**点卡片标题展开**，
里面是这一路自己的筛选条件与「重扫 / 重选 / 删除」。各来源互不干扰 ——
重扫其中一个，别的一张都不动；删掉一个，只有它名下的作品跟着走。

### 筛选：只导入你想要的那些

每个来源各带一套：

| | |
|---|---|
| **只要** | 留下匹配的。`*.jpg`、`IMG_?`、或者干脆写 `猫` |
| **排除** | 踢掉匹配的。`thumb`、`*_preview.*` |
| **正则** | 打开就按正则表达式理解（`^IMG_\d{4}$`）；关着时 `*` 和 `?` 是通配符，什么都不写就当「文件名里带这几个字」 |
| **格式** | jpg / jpeg / png / webp / avif / gif / bmp，逐个勾 |
| **最小边长** | 挡掉图标和缩略图。默认 200px，也可以不限 |

几处刻意的宽松：

- 模式同时拿**带后缀的文件名**和**去掉后缀的名字**去比 ——
  写 `*.png` 的人想的是前者，写 `^IMG_\d{4}$` 的人想的是后者，两种都能用。
- 模式里**带正斜杠**就改用整条相对路径来比，于是 `2024/` 就是「只要 2024 那个子目录」。
  （反斜杠不算 —— 正则里 `\d`、`\.` 满地都是。）
- **正则写错不会崩**，卡片上如实显示哪一条错在哪里。

其余照旧：每个来源最多 800 张，含四层子文件夹，跳过隐藏目录与缩略图目录；
**文件名当作品名**（自动去掉 `01_` 这类序号前缀），**上层文件夹名当作者名**
（网址来源则用这个来源的名字）；比例、主色色卡、占位图都在本地算出来，
和内置作品用同一套呈现（色卡、筛选、收藏都能用）。
「播放范围」里会多出 **我的图库** 和 **每日新作** 两个选项。

## 五之二、AI 补全（可选，默认关闭）

「每日新作」从 Commons 抓回来的条目，流派、材质、尺寸、导览多半是空的；
「自定义图库」更彻底 —— 标题就是文件名，作者就是上层文件夹名，`IMG_2043` 那种名字
在展墙上挂着并不好看。这一版可以**接你自己的多模态大模型**，让它看一眼图，把这些字段补上。

**设置 → 图库 → AI 补全**，填四样：接口格式、接口地址、密钥、模型。

| | |
|---|---|
| 接口格式 | **自动识别** / OpenAI / Anthropic。地址里带 `anthropic` 或 `/messages` 就按 Anthropic 走，其余按 OpenAI |
| 接口地址 | 填到 `/v1` 即可，也可以把完整地址贴进来。本机模型如 `http://localhost:11434/v1`（Ollama）、`http://localhost:1234/v1`（LM Studio） |
| 密钥 | OpenAI 格式发 `Authorization: Bearer`，Anthropic 格式发 `x-api-key`。默认遮起来，点「显示」看明文 |
| 模型 | 必须是**能看图**的模型 |

**一个接口下还可以存好几把密钥、好几个模型。** 密钥或模型框里换一个值，
旧的那个不会丢 —— 它会变成下面一排小标签，点一下换回去，点标签上的 × 忘掉它。
密钥在标签上只露头尾（`sk-abc…7f2e`）。每个接口各记各的，最多各 8 个。
手上有几把限额不同的密钥、或者想在便宜模型和好模型之间来回切时，不用再粘来粘去。

**可以存好几套接口，随时切。** 最上面那个下拉列着已存的接口，选「＋ 新建接口」再加一套；
每套有自己的名称（不填就用域名当名字）、格式、地址、密钥、模型，旁边有「复制」和「删除」。
想拿本机 Ollama 跑白天、云端模型跑夜里，或者手上几个供应商轮着用，切一下下拉就行，
不用把地址密钥反复粘来粘去。最多存 16 套。

填完点**测试连接**。它分**两步**问：

1. **先纯文字** —— 发一句「把『你好』译成英文」。这一步验的是地址、密钥、模型名对不对。
2. **再看图** —— 现画一张「白底红圆」发过去问它看到了什么。这一步验的是这个模型能不能读图。

分开问是有道理的：**识图补全**要多模态模型，**作品信息多语言**只用到文字。
第一步过了，多语言那一整块就解锁；第二步没过，也只是识图这一路走不通而已，
状态行会照直说：「接口通了 · 文字可用 · 多语言已解锁 · 但这个模型看不了图片」。

**哪一步不通，都会给一张诊断卡。** 不是把接口那句 `HTTP 400 · {"error":{"code":"1210"…`
原样甩给你，而是先认出这是十几种常见毛病里的哪一种，再给几条照着改就行的建议：

| 认出来的 | 给的建议 |
|---|---|
| 模型不认图片 | 说明识图要多模态模型（名字里常带 v / vl / vision），按你的服务商列几个能识图的型号，**点一下就填进模型框**；顺带提醒这不挡多语言那条路 |
| 模型名不认识 | 对拼写、大小写和前缀（有些家要写成 `厂商/型号`）；这个接口下存过别的模型就提示去下面小标签里换 |
| 密钥没过 | 重新复制别带空格换行；密钥要跟地址是同一家的；地址像 Anthropic 却选了 OpenAI 格式时会一并点出来 |
| 地址上没有接口 | 填到 `/v1` 就行，并把**这一次实际请求的完整地址**亮出来 |
| 连不上 | 先点「授权访问」；这个地址得允许浏览器直连（CORS）；本机模型要设 `OLLAMA_ORIGINS=chrome-extension://*`；`http://` 可能被当混合内容拦下 |
| 限流 / 余额 / 超上下文 / 内容审核 / 5xx | 各给各的下一步：调并发、看余额、减小打包件数、开重试…… |

服务商是按地址认的：智谱、OpenAI、Anthropic、通义、豆包、Kimi、硅基、MiniMax、
阶跃、Gemini、OpenRouter、Mistral、Groq、xAI、DeepSeek，以及 `localhost` 上的本机模型。
认出来了就给这一家**值得先试**的型号，认不出来就给通用建议。

> **给的都是候选，不是结论。** 哪家有没有多模态、哪个型号能不能读图，一直在变
> —— DeepSeek 就是个例子：一度没有，后来有了。所以长廊不写死「这家不行」，
> 界面上每一个「能识图」都必须是**真发过一次请求**测出来的。这就是下面这个按钮的意思。

### 探测模型：谁能读图，测出来说了算

**测试连接**旁边是**探测模型**。点下去它做三件事：

1. `GET {接口地址}/models` —— 问这个接口自己有哪些模型。拉不到就退回「你存过的那几个 + 这一家值得先试的」。
2. 排个先后：名字里带 v / vl / vision 的先探（只影响顺序，不影响结论）；
   嵌入、重排、语音、画图这些根本不是聊天模型的，直接跳过，不浪费请求。
3. 挨个**真跑两次**：一句纯文字，一张 96×64 的小图。

结果是一份带颜色的清单：

| | |
|---|---|
| 🟢 绿 | 文字与识图都通过 —— 这个能用来补全 |
| 🟡 琥珀 | 只有文字通过 —— 翻译够用，补图不行 |
| 🔴 红 | 连文字都没通过，后面挂着接口原话 |

**点一行就把它设成当前模型。** 清单存在这一档下面，下次打开还在。
一次最多探 14 个；探到一半可以停。

小心思两处：连文字那一关都没过的模型，**不会**再白发一张图片；
「这个模型不认图片」这类 400 也不再脱掉 `response_format` 重试一遍
—— 那一次重试注定还是同样的错，省下来就是省一半请求。

### 文字与识图可以分开配

翻译只用到文字，补全要看图。这两件事可以**各用各的接口和模型**：

**设置 → 图库 → 文字与识图** 里有个开关。关着＝两件事共用当前这一档（默认）；
打开之后给两个下拉：

| | |
|---|---|
| 文字用 | 翻译作品信息、译界面语言包 |
| 识图用 | 看图补全每日新作与自定义图库 |

便宜的小模型管翻译、贵的多模态只在补图时才动，是很自然的分工；
本机 Ollama 跑翻译、云端模型管识图也一样。两个下拉旁边各挂一个
**已实测 / 未实测**的小标签 —— 这一档在这一件事上到底行不行，一眼就能看到。

**测试结果是按档记的。** 换了地址，这一档整份凭证作废；只换了模型，
作废的只是「识图」那一项（文字那一关跟具体型号关系不大，留着）。
「多语言」解不解锁，看的是**文字那一档**测通没有 —— 跟识图那一档无关。

> 截图里那个例子：地址填的是 `https://open.bigmodel.cn/api/coding/paas/v4`。
> 诊断卡除了说「这个模型能对话，但不认图片」，还会额外点一句：
> **`/api/coding/` 是编程专用端点，识图请改成 `https://open.bigmodel.cn/api/paas/v4`**。

**三种触发方式**

- **手动**：点「立即补全」，按钮下面出现进度条与逐张清单，再点一次就是停止。
- **自动**：新作品一入库就补。每日新作抓完当场补；自定义图库扫完文件夹当场补，
  没补完的下次打开新标签页接着补。
- **定时**：关闭 / 每小时 / 每 6 小时 / 每 12 小时 / 每天 / 每 3 天 / **自定义**（分钟 · 小时 · 天，最短 15 分钟）。定时是用来**清扫漏网的**——
  每日新作由后台服务处理，开不开标签页都跑；自定义图库的图片只有页面里读得到
  （目录句柄拿不到后台去），所以那部分要等你打开一次新标签页。

**它会补什么**

两套提示词，分开走：

- **每日新作**当名画编目：中文译名、材质、流派、地区、题材、看点，
  以及一段 120–200 字的导览。已知的英文原名、收藏机构这些**不动**，只填空着的格子。
- **自定义图库**当**普通图片**处理 —— 提示词里第一句就是「它可能是照片、截图、插画、
  设计稿、扫描件，也可能是绘画，先看清楚它到底是什么，别默认它是名画」。
  标题要求「用一句朴素的话说清画面里是什么，八到十六个字，像相册里给照片起的名字」，
  作者一栏**只有画面上真有署名、水印、落款时才填**，否则宁可空着。

**几条克制的规矩**（这些是补全好不好用的关键）

- **词表是封闭的**。流派只能从内置的 21 个里挑，地区只能从 7 个里挑，题材只能从词表里挑
  —— 模型自己编的标签会被丢掉。这样筛选面板里不会长出一堆野生标签。
  自定义图库多一档日常题材（建筑 / 食物 / 草木 / 天空 / 山峦 / 树林 / 交通工具 / 器物 /
  图案 / 文字 / 运动 / 服饰 / 星空 / 机械），内置藏品用不到，只有认出来时才会出现。
- **默认只填空着的字段**，已经有的一律不动。要覆盖得自己打开「覆盖已有字段」。
- **标题处理**三档：**只换机器名**（默认）只动 `IMG_2043`、`DSC00123`、
  `Screenshot 2024-01-01 at 12.30.45`、`微信图片_20240101`、`截屏2024-01-01 下午3.20`
  这类「前缀＋一串数字」的名字；`Photo of a cat`、`奶奶家的院子` 这种有内容的标题不碰。
  另外两档是「总是重写」和「不动标题」。
- **作者**：自定义图库里那个「作者」其实是上层文件夹名。`Downloads`、`新建文件夹`、
  `截图` 这种一看就没意义的会被清空；`2019 京都` 这种有意义的保留。
- **办公模式的标记只往安全方向拨**：模型说「这张不适合办公室」就标上，
  说「适合」不会把已经标过的解开。
- **失败重试**：不重试 / 1 次 / 2 次 / 3 次 / 直至成功 / 自定义（上限 20）。
  只对**值得再试的**失败重试 —— 限流（429）、服务器抽风（5xx）、网络断一下、
  模型这次没按 JSON 回话；密钥不对（401）、地址不对（404）、请求被拒（400/422）
  一次都不多试，试一百遍也还是那样。间隔逐次拉长（0.6 秒起，×1.8，封顶 20 秒），
  「直至成功」最多 30 轮，随时可以按「停止」。
- **单条重试**：补全清单里每一行右边有个 ↻，只重来这一张。
  失败那行一直显示，成功那行鼠标移上去才出现（改坏了想重补也行）。
  重完就地把那一行换掉，存下来的记录同步更新。
- 补过的会打一个记号，不再重复花钱。想重来点「清除补全记录」（已经写进去的字段不会退回原样）。
- 读不到图片（比如文件夹权限被系统收回了）**不算补过**，下次还会再来；
  这种情况下连接口都不会打。

**看得见在补什么**

补全时按钮下方是一条进度条，底下跟着一份逐张清单，边补边长：

```
● 雨后的石阶            10 项
  IMG_2043
● 楚门的世界 电影海报     8 项
  IMG_2044
● Along the River …
  读不到图片 · HTTP 404
```

每行第一行是补完的名字，第二行是原来的名字（没改名就不显示），右侧是这一张补上了几个字段；
鼠标停上去能看到具体是哪几个字段、以及试了几次。最右边那个 ↻ 单独重来这一张。失败的那行是红点，第二行直接写原因
（网址会被去掉，留下真正有用的那截）。

清单跑完不会消失，关掉设置再打开还在，最近 200 条存在本地；不想看了点「清空这份记录」。
后台定时补的那些也会记进同一份清单，下次打开设置就能看到夜里补了什么。

**提示词是打开的**

设置 → 图库 → AI 补全 → **提示词**（点标题展开），三个框，就是真正发出去的原文：

| | |
|---|---|
| 系统提示词 | 两套共用的那几条铁律 |
| 名作提示词 | 每日新作用这份 |
| 通用图片提示词 | 自定义图库用这份 |

框里花括号包着的是**占位符**，发出去之前会换成真东西：

`{title}` `{artist}` `{year}` `{museum}` `{file}` `{folder}` `{dims}` —— 已知线索
`{shape}` —— 要模型输出的 JSON 骨架
`{vocab}` —— 词表约束（流派 / 地区 / 题材 / 画幅 / 办公模式 / 把握）
`{movements}` `{regions}` `{tags}` —— 单独的词表
`{noteLen}` —— 介绍字数要求，跟着「生成作品介绍」开关走

写错的占位符会**原样留在文本里**，一眼就能看出没生效。
点「预览」能看到**这一刻真正会发出去的完整内容**——线索用的是你库里第一件待补作品，
不是编的样例；旁边有「复制」，可以贴到别处调。

改过的那份右上角会出现「已改」角标，点「恢复默认」回到内置文案。
框里始终显示**真正在用的那份**：没改过时显示内置原文，你把它改回一字不差，也会被当作没改
——这样以后内置文案更新了，你还能跟着走。

> 改坏了不会出安全问题：**词表过滤是在代码里做的**，模型返回什么标签都得先过一遍白名单，
> 提示词里怎么写都污染不了筛选面板。但 `{shape}` 删掉，模型就不知道该回什么结构了。
>
> 三份提示词都是中文写的，要求模型同时给中英两版结果，所以英文界面下也照常工作；
> 想换成英文提示词，直接在框里改掉就是。

**开销与稳妥处**

- 发出去的是**缩到 1024px 以内的 JPEG**，不是原图。
- 每轮张数可选 5 / 10 / 20 / 50 / 100 / 200 或**自定义**（1–2000），默认 20；
  并发可选 1–4 或自定义（上限 8），默认 2，每次之间隔 250 ms。
- 页面和后台各有一份，靠存储里的一把**租约**互相避让，不会把同一批图片补两遍。
- 有些兼容接口不认 `response_format` 或 `temperature`，被 400 顶回来会**自动脱掉重发一次**。
- 模型爱把 JSON 包在代码块里、前后再说一句话，都会剥掉再解析。

> **接口地址一留空，整套功能就是关的**，两个图库完全沿用原来的规则，一个请求都不会发。

## 五之三、说你的话（多语言，需要接口）

长廊内建的只有中文和英文。但「艺术」这件事不该只对懂这两种话的人开放 ——
所以从 v1.15.0 起，长廊只认**两个语言位置**：一个**母语**，一个**外语**。
具体是哪两种由你定，从 **78 种语言**里挑，挑不到就自己填一个名字。

**设置 → 呈现 → 语言 · 时钟**

| | |
|---|---|
| 母语 | 你自己的话。界面默认跟着它走 |
| 外语 | 另一面。墙签翻过去看到的就是它 |
| 界面用 | 母语 / 外语 / 跟随系统（系统语言更接近哪一个就用哪一个） |

中文和英文**任何时候都能选**，不需要接口。想换成第三种语言，
得先在「图库 → AI 补全」里把**文字那一档**测通（只要文字那一步过了就行，
识图通不通不影响）——
因为界面文案和作品信息都得现场译出来。没测通时下拉里只有中英两档，
下面有一行说明和一个「去设置接口」的按钮，点一下直接跳过去。

**两样东西会被译**

- **作品信息** —— 标题、艺术家、材质、收藏机构、地点、看点、那段导览，
  还有年代与生卒里的「约 / 世纪 / 之后」这类限定词。
  可以选**译哪些**（全部 / 内置馆藏 / 每日新作 / 自定义图库）和**一轮译几件**，
  以及**一次请求打包几件**（打包多了省钱，打包少了稳当）。
  译的时候有进度条和逐条清单，跟 AI 补全那一套是同一副样子。
- **界面文案** —— 设置面板、按钮提示、流派 / 地区 / 题材 / 色系 / 墙面 / 纹理 / 画框
  这一整套筛选词表，一共 **580 条**。分批送出去，**只译一次**，之后存在本机，
  换回来再换过去都不用重译。

**几条让它不至于翻车的规矩**

- **底本挑过**：目标是中日韩就拿中文原文去译，别的一律走英文那一份 ——
  英文那份本来就是写给全世界看的，转到拉丁语系损耗最小。
- **占位符不许动**：`{n}` `{a}` `<em>` 这类会明确要求原样保留，位置可以按语序挪。
- **专名不许译**：OpenAI、Ollama、LM Studio、CORS、JSON、`chrome-extension` 这些留着。
- **只收认得的字段**，长度掐住 —— 模型顺手写篇小作文进来也进不了库。
- **回落链**：当前语言 → 另一面 → 英文 → 中文。哪一格没译到就往下顺一位，
  **绝不开天窗**，也绝不露出内部键名。
- **从右往左的语言**（阿拉伯语、希伯来语、波斯语、乌尔都语）会把整页的书写方向翻过来。

**译文存在哪** —— 单独一层「覆盖层」，不动原库。内置馆藏是只读的静态 JSON，
每日新作与自定义图库也不该被译文撑大；换语言不动原库，想清掉就是一句话的事
（「清掉译文」会把这两种语言的作品译文与界面语言包一起清干净）。

**新作品会自己补上** —— 开着「作品信息也用这两种语言」时，每次打开新标签页，
补全跑完之后会顺手译一小批（一轮至多 12 件），不用你惦记着回来点一次。

## 六、离线是怎么做的

作品图片在第一次显示后会存进浏览器本地的 IndexedDB；下次打开新标签页直接读本地，
不再请求网络。后台每隔三小时会悄悄预取几幅还没缓存的作品，并且每次换画时预取接下来的三幅。
**缓存满了会怎样**：写入累计到 12 MB 就检查一次占用；超过上限时按「**最久没看过的先删**」清理，
一直腾到上限的九成为止（留出余量，免得刚删完又满）。**收藏过的作品排在最后才动**。
删掉的只是本地那份副本，下次显示时会重新取一遍，设置、收藏、历史都不受影响。

图片与索引分成两个 store 存：`images` 只放图，`meta` 只放 `{大小, 最后使用时间, 作品 id}`。
统计占用和执行淘汰都只读 `meta`，几百兆的图片不会因为「算一下用了多少」被整个读进内存——
命中缓存时也只更新 meta 的时间戳，不再回写整张图。

断网时仍会正常显示已缓存的作品；如果某幅完全没缓存过，会退回到内置的极小占位图（每幅约 0.5 KB，已随扩展打包）。

想一次备齐：设置 → 离线缓存 → **缓存全部作品**。按默认画质约需 300–600 MB。

### 缓存到底在磁盘的哪里

图片存在 Chrome 分配给本扩展的 IndexedDB 里。设置页会自动识别你的系统并显示实际路径，旁边有「复制路径」：

| 系统 | 路径 |
|---|---|
| **Windows** | `%LOCALAPPDATA%\Google\Chrome\User Data\Default\IndexedDB\chrome-extension_<扩展ID>_0.indexeddb.leveldb` |
| **macOS** | `~/Library/Application Support/Google/Chrome/Default/IndexedDB/chrome-extension_<扩展ID>_0.indexeddb.leveldb` |
| **Linux** | `~/.config/google-chrome/Default/IndexedDB/chrome-extension_<扩展ID>_0.indexeddb.leveldb` |

（用的不是 Default 配置文件时，把 `Default` 换成 `Profile 1` 之类。扩展 ID 在设置页里就是完整显示的。）

不过那是 LevelDB 数据库文件，**不能直接当图片浏览**。要拿到能用的图片，用下面这个：

### 一键导出图片（Windows / macOS 通用）

设置 → 离线缓存 → **导出已缓存作品**。
每幅作品会按 `艺术家 - 作品名 (年代).jpg` 写进 **下载 / Corridor Gallery /**，文件名做过 ASCII 净化，
中文系统、英文系统都不会出错。导完点旁边的 **打开文件夹**，会直接在 Windows 资源管理器 / macOS 访达 /
Linux 文件管理器里定位到那个目录——不用自己去翻路径。

按 `D` 也可以随时单独下载当前这一幅。

## 七、Chrome 底部那条白色页脚

那条写着扩展名和「Customize Chrome」的白条**不是本扩展的界面**。
从 Chrome 138 起，只要新标签页是被扩展接管的，Chrome 就会在底部加这条官方页脚，
用来告诉你是哪个扩展在提供这个页面——**扩展无权隐藏它**，这是浏览器行为。

关掉它只要一步，两种方式任选：

1. 在新标签页上**右键点那条白条** → 选「隐藏新标签页上的页脚」
2. 或点白条右侧的「**自定义 Chrome**」→ 侧栏拉到最下方 → 关掉「在新标签页上显示页脚」

改完如果没立刻生效，重启一次 Chrome。设置页里也放了这段说明，随时可以查。

## 八、关于图片来源（请读一下）

**Google Arts & Culture 没有面向个人开发者的公开 API**，官方接口只对合作的文博机构开放，
直接抓取其页面既违反服务条款也随时可能失效。所以本扩展采用的是同样合规、同样高清的路线：

- 全部图片来自 **Wikimedia Commons** 的公有领域高清扫描，多数正是各大博物馆（含 Google Art Project）
  公开释出的原始文件——例如《星月夜》用的就是 Google Art Project 的 44567 × 35291 版本。
- 每幅作品的详情页都附有两个外链：**在 Wikimedia Commons 查看**（原始文件与授权信息）、
  **在 Google Arts & Culture 搜索**（跳转到官方站点检索同一件作品，可看超高倍放大与馆方策展）。
- 106 幅作品全部处于公有领域（作者去世逾 70 年，或由收藏机构以 CC0 释出）。
  文字导览为本项目原创撰写。

图片按 Wikimedia 的标准尺寸阶梯请求（120 / 250 / 330 / 500 / 960 / 1280 / 1920 / 3840 px），
按你的屏幕分辨率自动选择，不会浪费流量。

## 九、隐私

- 不收集、不上传任何数据；没有统计代码、没有账号、没有远程配置。
- 默认情况下，网络请求只发往 `upload.wikimedia.org`（取图）、`commons.wikimedia.org`（每日新作的公开 API 与来源页）、`www.wikidata.org`（补中英文名）。设置、收藏、历史、缓存、自定义图库全部存在本机。
- **唯一的例外是你自己开的「AI 补全」**：开了之后，被补全的图片会缩成 1024px 以内的 JPEG，
  发到**你自己填的那个接口地址**，不经过任何第三方。密钥只写在本机 `chrome.storage.local`，
  只随请求发往那一个地址。**地址留空就完全不发。**
  自定义图库里如果有私人照片，请自行斟酌是否打开这个开关，以及要不要用本机模型
  （`http://localhost:11434/v1` 这类，图片连机器都不出）。
- 权限说明：`storage`/`unlimitedStorage` 存设置与图片缓存；`alarms` 用于后台预取与定时补全；
  `downloads` 用于「下载原图」；`host_permissions` 仅限 Wikimedia 两个域名。
  AI 补全用的是 **可选权限**：只有你填了接口地址并点「测试连接 / 立即补全 / 去授权」时，
  浏览器才会弹窗问你要不要放行**那一个域名**；不用这个功能就永远不会问。
- `topSites`（v1.20.0 新增）是**可选权限**：装上时不申请、不弹窗。只有你打开「暂歇」
  那一屏并点「授权读取常访问站点」时才申请一次，同一个面板里随时能撤回。
  这一屏读到的只有站点名与网址，读不到你什么时候去过、去过几次；
  它也**不取站点图标、不发任何网络请求** —— 取图标要么再加一条权限，
  要么把你常去的站点报给第三方图标服务，两样都不值得。
- `declarativeNetRequestWithHostAccess`（v1.20.0 新增）只做一件事：把发往**本机地址**
  （`localhost` / `127.x` / `0.0.0.0` / `::1` / `*.local`）的请求的 `Origin` 头改写成
  那个地址自己，好让 Ollama 这类本机服务的来源检查放行。它带 `WithHostAccess` 后缀，
  意思是**只在你已经授权的地址上生效**，安装时不会多出任何权限提示；规则还锁死在本扩展
  自己发出的请求上（`initiatorDomains`），网页发往同一个端口的请求不受影响。
  公网接口的 `Origin` 一个字都不动。

## 十一之三、v1.20.0 这一版改了什么

**本机模型终于连得上了；右下角多了一个「去除」；今日画夹能滚了。**

### 一、Ollama 那个 403，根本不是密钥的问题

现象：接口地址填 `http://localhost:11434/v1`，点「测试连接」，
回来一句 **`HTTP 403 · 未知错误`**，诊断卡还煞有介事地说「密钥能认，
但没有调这个模型的权限」，让你去控制台开权限——可本机模型压根没有控制台。

真因：Ollama（LM Studio、llama.cpp 也一样）在服务端检查请求的 `Origin` 头，
默认只认 `http://localhost`、`http://127.0.0.1` 这几个来源。而浏览器给**扩展**
发出去的请求，一律打上 `Origin: chrome-extension://<扩展 id>`——不在白名单里，
于是被 CORS 中间件整个挡下，回一个 **403 而且响应体是空的**。
响应体是空的，所以界面上只剩「未知错误」四个字，什么线索都没有。
这是服务端的检查，不是浏览器的 CORS，所以「扩展有主机权限就能跨域」在这里救不了。

改法有两层：

**第一层，让它自己就通。** 新增 `declarativeNetRequestWithHostAccess` 权限，
`src/localnet.js` 在你给某个**本机地址**授权之后，铺一条动态规则，
把发往这个地址的请求的 `Origin` 改写成那个地址自己
（`http://localhost:11434`）。在 Ollama 看来这就是本机网页发来的，照默认白名单放行。
三条自我约束写在那个文件的开头：只改本机地址、只改本扩展自己发的请求
（`initiatorDomains` 锁死在扩展 id 上）、没授权就不生效。

**第二层，万一改写走不通，话得说清楚。** `diag.js` 现在先看地址是不是本机：
是本机 + 403，结论就是「本机模型把长廊挡在了门外（不是密钥的问题）」，
下面按 macOS / Windows / Linux 给出三条能一键复制的命令：

```
macOS     launchctl setenv OLLAMA_ORIGINS "chrome-extension://*"
Windows   setx OLLAMA_ORIGINS "chrome-extension://*"
Linux     OLLAMA_ORIGINS='chrome-extension://*' ollama serve
```

顺带：本机地址那一档现在会提示「本机模型一般不需要密钥」，密钥框留空即可；
地址写成 `0.0.0.0` 或 `::1` 的，诊断会劝你换成 `127.0.0.1`。

### 二、「去除」：收藏的反面

右下角星形旁边多了一个按钮（快捷键 `X`）。点下去，这一幅**不再参与轮换，
藏品库里也不再列出**——办公模式只管「轮换时跳过」，藏品库照旧全都列，
「去除」是唯一会让作品从藏品库里消失的东西。

它不是删除：存的只是一份 id 名单（`chrome.storage.local` 的 `gone`），
作品数据一个字节都没动。**设置 → 数据 → 已移除**里列着所有被去除的作品，
可以逐幅「放回」，也可以「全部放回」。

点完不弹确认框，改成底部亮出一条 **「已移除《XX》· 撤销」**，五秒内可以反悔——
连着整理藏品时不会被一串确认框打断，手滑了也找得回来。

### 三、今日画夹滚不动

画夹一次最多摊五幅，窄窗口里它们会换行，竖幅又特别高，于是下半截露在屏幕外面，
而那块台面是 `flex` 居中且不可滚动的——看得见截断，却没法滚下去看。

三处一起改：台面自己能滚（`overflow-y:auto`），纵向对齐用 `align-content: safe center`
（摊得下时居中，摊不下时从顶上排，第一排不会被顶到看不见的地方）；
卡片宽度跟着张数收窄（四幅、五幅时上限更小），常见窗口一排就摊得下；
画的高度封在 `46vh`，竖幅不再把一排撑成两屏。
台面那层「桌面反光」原来挂在台面上，会跟着内容一起滚——移到页脚上去了。

### 四、暂歇：一键把长廊关掉

顶栏设置左边多了一个开关（快捷键 `P`）。按下去，这一页不展画了，
改成一块安静的落脚地，上面是你常去的那几个站点。再点一次回到展出。
状态存在设置里，所以**跨标签页同步、重启浏览器也还是关着**，直到你再点一次。

**为什么不是「真的关掉扩展」**：Chrome 的新标签页覆盖是全有或全无——
扩展一旦接管，就没法在页面里让位给原来那一页（`chrome://new-tab-page` 也跳不过去）。
真要让位只能去 `chrome://extensions` 停用整个扩展，那不叫「临时」。
所以诚实的做法是：这一页还是长廊的，只是不展画。

**三种排版**（设置 → 呈现 → 暂歇）：

| | 样子 | 适合 |
|---|---|---|
| **展签墙**（默认） | 墙还在、灯还亮着，只是墙上挂的是展签不是画。错落着，指上去轻轻抬起 | 跟「开着」时是同一个房间，过渡最自然 |
| **闭馆告示** | 画撤了墙空了，中间「暂歇」两个大字，一条金线，下面两列编号条目 | 最像「真的关掉了」 |
| **目录索引** | 展览手册最后那页的索引：站点名在左、网址在右，中间一行点线牵着 | 最安静、最书卷气 |

**展签墙有两种皮**（只在展签墙这一种下出现）：

- **简约**（默认）：跟作品展签同一种奶油色纸。
- **彩签**：一排签从左到右铺成一柄色卡扇面，珊瑚红 → 琥珀 → 绿 → 青 → 蓝 → 紫，
  每张签自己也是左浅右深的一道渐变。

> 配色是在 `pause.js` 里算好、以 `--c1/--c2/--ink/--num/--dim` 写成行内变量交给 CSS 的。
> **为什么不用 `oklch()`**：它要 Chrome 111，而这个扩展的底线是 110。
> 所以用 `hsl` 加一条亮度补偿——黄绿本来就显亮要压一点、蓝紫显暗要提一点，
> 但补过头蓝紫就发白，所以幅度只给 3，再给冷色多一点饱和把颜色兜住。

**站点从哪来，两处合流**：

- **自己钉的** —— 设置里手动加，存在本机，零权限。排在前面。
- **Chrome 的常访问榜** —— 要 `topSites` 权限，所以做成**可选权限**：
  第一次开启时才申请一次，同一个面板里随时能撤回。没授权也能用，只显示自己钉的。

按域名去重，自己钉的优先。**「最多显示几个」削的是 Chrome 那张榜，
自己钉的一定会显示** —— 不这样的话，钉满之后再从墙上钉一个，会看着像没反应。

Chrome 给的标题常常是一整句，取第一个分隔符之前那一段挂上去就够了。
分隔符除了 `- – — | · :`，还认中文的 `，、。：` ——
这几个几乎不会出现在站名里，而「扣子编程，你的 AI 开发伙伴，…」这种截了才好看：

| 原标题 | 挂上去的 |
|---|---|
| 扣子编程，你的 AI 开发伙伴，一站式… | 扣子编程 |
| 百度一下，你就知道 | 百度一下 |
| 智谱 \| BigModel 平台 | 智谱 |
| 知乎 - 有问题，就会有答案 | 知乎 |
| GitHub: Let's build from here | GitHub |

**不必翻设置也能钉**：墙的末尾有一张「＋ 钉一个站点」，点一下就地展开一个小表单；
自己钉的那几张指上去右上角有个 × 能撤。设置里那份清单仍然在，两边是同一份数据。

> **两件刻意不做的事。** 一是不取站点图标：`topSites` 只给站点名与网址，
> 要图标就得再加一条 `favicon` 权限（又一次警告），或者去第三方图标服务取——
> 那等于把你常去的站点报给别人。这一屏一个网络请求都不发。
> 二是不碰历史记录：读到的只有 Chrome 算好的那张榜，读不到你什么时候去过、去过几次。

> **一个要知道的落差**：`topSites` 给的是 Chrome 自己算的「最常访问」，
> **不含**你在原来那个新标签页上手动固定的快捷方式——那些 Chrome 不通过 API 给出来。
> 想让它们出现，在「自己钉的」里加一遍。

每一条都是真的 `<a>`，所以中键、Cmd 点击、右键「在新标签页打开」全都照常管用。

### 五、备份与恢复：换台机器，配置跟着走

**升级本来就不丢配置。** 同一个扩展 id 下，`chrome.storage.local` 在版本更新时
原样留着——1.19.1 → 1.20.0 实测过：设置、接口档（档名、格式、地址、密钥、
存过的那几把密钥与模型、「测试连接」的实测结果）、收藏，一样不少。

丢的是另一种情况：**把扩展删掉重装**，或者换一台机器。那时候扩展 id 变了，
存储是全新的。所以这一版加了「备份与恢复」（设置 → 存储）。

**格式是 JSON，不是 Markdown。** 这份东西是给机器读的：Markdown 好看，
但没有类型，数组、布尔、嵌套结构一转成表格或列表就会丢，倒回来还得靠猜。
JSON 原样进、原样出，一个字段都不掉。

**带走哪几块自己勾**：设置与接口档 / 收藏与已移除 / 浏览历史 / 作品译文 /
界面语言包 / 每日新作 / 图库网址来源。导入时也按同一组勾选来，
文件里有、但没勾的一概不碰。

**接口密钥三条路**：

| 选项 | 文件里 | 导入时 | 适合 |
|---|---|---|---|
| 不带 | 搜不到密钥 | 直接导 | 只想同步设置，密钥手动再粘 |
| 口令加密 | 只有密文 | 要同一个口令 | 默认推荐。文件落到云盘也不泄密 |
| 明文 | 看得到 `sk-…` | 直接导 | 最省事，但这份 json 从此得当密码本收着 |

加密用的是浏览器自带的 Web Crypto：PBKDF2-SHA256 派生（25 万轮）＋ AES-GCM-256，
盐与 IV 每次导出重新摇，一起写进文件（它们不是秘密，秘密只有口令）。
**加密的只有密钥那几个字段**，别的照旧可读——所以口令忘了，其余配置照常恢复，
只是密钥要重填一次。口令错了会明确报「口令不对，或这个文件被改过」，
而且**一个字都不会写进存储**：解密放在所有写操作之前。

**导入两种合法**：

- **覆盖**——勾中的那几块整块换成备份里的。重装之后恢复用这个。
- **并入**——只添不删：接口档按编号合并（本机已有的那一档留着），
  收藏、已移除、图库来源并进来。从另一台机器搬配置用这个。

**备份里没有的两样**，都是「换台机器也没意义」的：图片缓存（几百 MB，
装回来自己会重新抓）；本机文件夹图库——浏览器不允许把目录授权带走，
换台机器也指不到同一个盘，所以只备份网址来源，文件夹要重新选一次。

> 一个当时没想到、测出来才发现的洞：选了「不带密钥」，密钥其实还在文件里。
> 因为 `settings.ai.key` 是「当前那一档」的平铺镜像，只清 `ai.list[].key`
> 还不够。这种「说了不带却带了」的错，不实跑一遍是看不出来的。

## 十一之三、v1.19.1 这一版改了什么

**三个都是「看着像没反应」的毛病：建不出接口档、快捷键漏字、Esc 按了不关。**

### 一、一个接口都没有时，建不出第一个接口档

接口档那个下拉框，列表为空时只剩「＋ 新建接口」一个选项，浏览器默认就把它选中了。
再点它，值没变，`change` 不触发——于是永远建不出第一档。删掉最后一档之后是同一个死局。

改法：列表为空时补一个 disabled 的占位项（显示「未配置」），下拉框的初始值回到空串，
选「＋ 新建接口」才算真的换了值。

### 二、按 `L` 打开藏品库，搜索框里先躺了个 l

藏品库一打开就把焦点交给搜索框，而键盘处理没有 `preventDefault`——那个 `l`
接着被打进了刚刚聚焦的搜索框。点按钮打开没这毛病，所以一直没被发现。

字母快捷键（`f` `z` `i` `l` `s` `c` `m` `d`）现在统一 `preventDefault`；
「焦点已经在输入框里」的情况在更上面就 return 掉了，拦不到正常打字。

### 三、Esc 看着失灵

键盘处理第一行遇到输入框就 blur 然后 return。于是框里躺着那个 l 的时候，
第一下 Esc 只是退出输入框、藏品库还开着；而 `i` / `z` / `m` / `空格` 又都被
「有面板开着」挡住——看起来像是 Esc 和快捷键一起坏了，得按第二下才活过来。

现在 Esc 落在输入框上时：框里是空的就顺手把面板也关掉；框里有字就只退出输入，
保留「再按一次才关」的两段式。

## 十一之二、v1.19.0 这一版改了什么

**这一版全部围绕「墙」：颜色能自己配了，灯能调了，材质推倒重做了一遍。**

### 一、墙面颜色：先把「看不清」这件事解决掉

原来把鼠标停在色卡上，会在色卡**上方**弹一个深色小气泡写颜色名。
两个毛病：深色墙上深色气泡本来就看不清；色卡换行以后，第二排的气泡正好盖住第一排的色卡。

改法不是把气泡调亮，而是**不要气泡**。色卡下面固定一行：指到哪读到哪，
顺带把色号一起报出来。谁也挡不着谁，对比度实测 17:1。

顺手把色卡分了组，并按用户点名加了一组新颜色：

| 中性 | 展厅色 | 柔彩（新） |
|---|---|---|
| 炭黑 · 石墨灰 · 鸽灰 · 暖灰 · 石膏米 · 展厅白 | 美术馆绿 · 勃艮第红 · 普鲁士蓝 · 陶土红 | **拿坡里黄 · 翡翠绿 · 珊瑚橙红 · 鼠尾草绿 · 灰玫瑰粉** |

最后一格是**自定义色板**：点开取色器，或者直接填色号。

> 顺带说一件以前写死、现在算出来的事：界面要不要跟着墙色反色，
> 原来是每种颜色手写一个 `light: true/false`。有了自定义色板就写不动了，
> 于是改成按 sRGB 相对亮度实算，阈值 0.22 —— 换算下来原来那十种一个都没变。

### 二、色调微调：饱和度与色温

在选定的颜色上再拧一点。两个滑杆，都在**线性光**里算：

* **饱和度** 0–200%。拧到 0 就是同亮度的灰。
* **色温** 冷 ↔ 暖。红蓝对拧，**拧完把亮度还原回去** ——
  调冷暖不该顺手把整面墙调亮或调暗。

这两个滑杆对**自带本色的材质同样有效**：选木饰面再把饱和度收一半，就是漂白橡木；
选黄铜再往冷里拧，就是发青的旧铜。

### 三、灯光

新的一组，四个东西：

* **灯数** 不打灯 / 1 / 2 / 3 / 4 盏。几盏就把墙横向分成几份。
* **亮度** 0–200%。
* **角度** −60°…+60°。这一项不只是挪光斑：**画框投影的方向跟着翻**，
  **贴图受光的那一面也跟着镜像** —— 贴图是照左上角来光烘出来的，
  灯挪到右边而受光面不动，一眼就假。
* **冷暖光** 冷白 ↔ 暖黄。

还有一件不在面板上、但影响很大的事：**纹理现在只在光扫得到的地方立体**，
背光处会平下去。真墙就是这样的。

### 四、材质：为什么以前「太假」，这次怎么改的

把 v5 的贴图铺开一看就明白了：**能量几乎全压在高频上**（细颗粒），低频几乎是空的。
于是每一种材质在屏幕上都长成同一副样子 ——「一块平色上撒了砂」。

真墙不是这样的。真墙的信息量在**大尺度**：批刀走过的一整片、滚筒的搭接带、
浇筑的色差、木头的山形纹、砖各自不同的深浅。近看的颗粒只是配角。

所以 v6 做了四件事：

1. **把能量搬回低频。** 颗粒交给共享的 grain 层，贴图只负责结构。
2. **新增共享的 mottle 层**（大尺度不匀），按与贴图**不成整数比**的尺寸平铺 ——
   两层的公共周期大到看不见，屏幕上那种「同一块在眼前出现三次」的重复感就散了。
3. **有本色的材料带上本色。** 木头是木头色、黄铜是黄铜色，不再被墙漆染。
4. **逐材质补上真正决定「像不像」的那个结构。** 举三个：

   * **木饰面** 以前只有竖条纹。这一版给每块板一个虚拟髓心，等距圆环再压扁 ——
     平锯木材的**山形纹**就出来了，另有管孔、髓射线、板缝。
   * **砖墙** 以前砖几乎看不见。真砖墙靠三件事成立：凹进去的灰缝、每块砖各不相同的深浅、
     砖面的麻点。而砖面本身是**平的** —— 倒角一宽就成了塑料积木，所以起伏压到极低，
     差别几乎全部交给颜色。
   * **威尼斯灰泥** 本体几乎是平的，靠光泽成像。一片压一片的抹痕只留下极细的一圈刀口线。
     （中途试过用梯度脊做边界，结果得到一圈圈闭合的「爬虫」—— 那不是抹痕，推倒重来。）

   **锦缎**与**花缎**也重画了：以前缎纹的节距缩到屏幕尺寸后只剩不到两像素，
   经纬方向的差别整个消失，等于纹样没画。这一版把节距放粗、明暗补上一档，
   花缎的主花还做成**鼓起来的**（衬纬把它顶起）并带一圈落影。

**石材与硬装**五种全部重做；**展墙做法**九种全部重做。

### 五、金属背景板（新的一组）

拉丝不锈钢 · 黄铜 · 红铜 · 耐候钢 · 锻黑钢 · 金箔。

金属自带本色，选中时接管墙面颜色（面板上会说明），但饱和度与色温照常可调。
金箔是一张张方箔叠贴的，接缝处双层更亮 —— 挂画在金箔墙上很好看。

### 六、顺带

* 抽屉里的色卡改成按自然宽度排，六个中性色不再掉下来一个孤零零的。
* 材质芯片的底色改用材质本色 —— 一眼看得出黄铜是黄铜。
* 配套的几个生成脚本也一并补齐（材质预览、房间参数表）。

## 十一之二、v1.15.0 这一版改了什么

### 一、接口报错，从「原样甩给你」变成「告诉你该怎么改」

原来接口不通，界面上就是一行 `HTTP 400 · {"error":{"code":"1210","message":"messages.content.type is invalid…`。
这句话是真的，但它没告诉你**该做什么**。

内容审核 / 5xx / 连不上 / 超时 / 模型不按 JSON 回话），然后给一张卡片：
**一句结论 + 几条照着改就行的建议 + 几个能点的型号 + 折起来的接口原话**。

**测试连接也拆成了两步**：先纯文字，再看图。这样「通了但这个模型不认图片」
不会被笼统地报成「连不上」—— 而这恰恰是最要紧的区分，因为下面这件事只用到文字。

### 二、母语 · 外语：长廊只认两个语言位置

## 十一之二、v1.14.3 这一版改了什么

**墙签：画作不再被它推来推去；点一下是真的翻面。**

**画作不动了。** 上一版把墙签改成 `width:max-content` 之后，宽度确实跟着内容走了，
但带来一个副作用：`.hang` 这一行（画框 + 墙签）是整体居中的，墙签一变宽变窄，
整行的宽度就变，画框跟着左右挪 —— 翻个语言，画就晃一下。

做法是给墙签在版面里留一格**恒定宽度**的位置（`.lb-slot`，`--lbw: clamp(190px,26vw,380px)`），
墙签本体在这一格里**绝对定位、贴着左边**，宽度仍然是 `max-content`、上限就是这一格。
于是布局只认这一格的宽度，跟墙签实际多宽无关 ——
画框位置纹丝不动，墙签的左端离画框永远是同一个 gap，内容长就往右伸、短就往左收。

测得的数：翻面前后画框左右缘完全一致（135 / 946），墙签左端也一致（985），
而墙签宽度从 205 变成 246。换四幅作品，那一格始终 380，墙签左端始终等于这一格的左端，
墙签宽度在 200–293 之间跟着内容变。

**翻面是真的翻。** 原来只是淡入淡出换个文字。现在是绕竖轴转半圈的闪卡动画：
`rotateY` 0° → 89°（这一瞬看不见）→ −89° → 0°，配 `perspective(1100px)`，
半途 245ms 时把内容换掉。宽度的跳变也正好藏在卡片立起来看不见的那一瞬里，
所以从头到尾看不出「宽度变了」这回事。动画期间再点会被忽略，转完自己清掉动画类；
系统开了「减少动态效果」就几乎不转。

**验证**：79 条纯逻辑单测 + 248 条端到端。墙签那一段重写成 11 条：
贴着格子左边、没占满整格、常规作品不折行、翻面时画框左右缘不动、墙签左端不动、
左端离画框的距离不变、内容真的换了语言、宽度跟着变、动画确实是 `matrix3d` 的三维翻转、
转完清掉动画类、连点不崩；再加换四幅作品时那一格宽度恒定、墙签始终贴左、宽度确实在变。

## 十一之二、v1.14.2 这一版改了什么

**设置标题栏那一排捋齐了；墙签宽度不再写死。**

**标题栏。** 原先那一排四个控件是四套尺寸：当前/全部那个小分段 26px、
明暗图标 34px、重置 36px、关闭 38px，圆角和描边也各不相同，挤在一起很毛躁。
现在统一成 **高 30px、圆角 8px、1px 描边、12px 字**，顺序也按使用频率重排为
**明暗 → 当前/全部 → 重置 → 关闭**。顺手把「设置范围」的默认值改成**当前**，
并且存进设置 —— 之前它只活在内存里，关掉标签页就忘了。

**墙签宽度。** v1.14.0 为了少折行把它从 `clamp(186px,15vw,244px)` 改成
`clamp(232px,20vw,336px)` —— 还是一个写死的数，只是写死得宽一点。
现在改成 `width:max-content`，**宽度由内容决定**，配一个下限 186px（太短的标签不至于窄成一条）
和一个上限 `min(34vw,380px)`（再长也不能把画挤掉）。
实测中文作品落在 200–293px，每一行都是单行；英文下最长的那几件顶到 380px 上限，
只有「Where Do We Come From? What Are We? Where Are We Going?」这种六十多字符的标题才真的换行 —— 那本来就该换。

`#label` 是 `.hang` 这个 flex 行里的一员，`flex:0 1 auto` 意味着空间不够时它会被压缩到
自然宽度以下。测试里专门比了一下「被压缩后的宽度」和「flex-shrink:0 时的自然宽度」，
两者相等，说明画框旁边的余量足够，墙签没有被挤瘦。

**验证**：79 条纯逻辑单测 + 239 条端到端。新增 10 条：标题栏四个控件同高 / 同圆角 /
同字号 / 同描边 / 顺序对、设置范围默认「当前」且记得住、墙签宽度＝自然宽度 /
落在上下限之间 / 常规作品不折行 / 换一幅宽度跟着变。

## 十一之二、v1.13.1 这一版改了什么

**设置面板能切浅色了；补全失败可以重试，也能只重来某一张；顺手修掉「关于」上面那条多余的线。**

**那条多余的线。** 上一版把「关于」也变成了一个分组，分组标题自带一条下边线，
而 `.about` 从很早以前就带着自己的 `border-top` —— 两条线挨在一起，中间只隔十几像素。
去掉 `.about` 那条即可，但选项页里 `.about` 上面没有分组标题，那条线还得留着，
所以改成 `.wrap .about` 单独保留。

**设置面板的昼夜。** 标题栏加了一个太阳 / 月亮按钮。切的**只是抽屉这一块** ——
画面、画框、墙色一概不动，那是展厅不是界面，把展墙也刷白反而不对。

做法上偷了个懒也讨了个巧：面板里那些「浮在暗底上的白色填充」
（`rgba(255,255,255,.05)` 之类）原本散在三十来条规则里，先把它们收敛成
`--f0/--f1/--f2/--f3` 四档变量；然后浅色模式只需要在 `#drawer` 上把
`--ink* / --hair* / --f*` 重新声明一遍，子元素靠自定义属性的继承全都跟着走。
真正需要单独盖掉的只剩十来条写死的深色（下拉选项底色、开关圆钮、滑块把手、
清单底色这些）。

一个非改不可的地方是**主色**：`--accent` 是从当前作品里取的，为深色面板调过亮度，
压在白底上根本读不清。所以另算一份 `--accent-lt` —— 同一个色相，明度压到 27–40%，
浅色模式里 `--accent` 直接指向它。于是浅色面板的强调色仍然跟着画走。

**失败重试。** `describeRetry()` 包在 `describe()` 外面，按 `ai.retry` 决定试几次，
间隔 0.6 秒起、每次 ×1.8、封顶 20 秒。关键是**分类**：`retryable()` 把
401/403/404/400/422 判成「白试」，429/5xx/网络/超时/模型没回 JSON 判成「值得再试」，
本机图片读不到判成「这一轮别试，留给下次」。测试里专门验了这条 ——
密钥错误配上「重试 3 次」，接口也只被打了一次。

**单条重试。** 清单每一行右边一个 ↻，调 `retryOne(id, box)`：只取这一张、
只写这一条，回来就地把那一行的 DOM 换掉，同时更新内存里和存储里的那份记录。
它会先看一眼存储里的租约 —— 后台正跑着一整批时不插队，
否则那边 flush 整份库时会把这一张的结果冲掉。

**验证**：79 条纯逻辑单测 + 186 条端到端。新增 37 条：横线没了、
昼夜（图标、落库、刷新后还记着、抽屉底色与文字都翻过来、浅色下正文对比度够、
画面那半边不受影响）、重试（五种错误分类 × 四档次数 × 真实限流接口）、
以及「点 ↻ 之后那一行变绿、接口只被重打了一次、存储里的记录也更新了」。

## 十一之二、v1.13.0 这一版改了什么

**设置抽屉重做：五页、可折叠、能搜；接口可以存好几套；定时与张数都能填自定义值。**

**设置为什么要重做。** 「缓存」那一页已经塞了四件不相干的事：离线缓存、每日新作、
自定义图库、AI 补全，加上导出、路径、Chrome 页脚、关于 —— 一路滚到底要转好几圈滚轮。
这一版拆成**五页**，把图库那三件事单独拎出来成一页「图库」，「缓存」改叫「存储」。

**每一组都能折叠。** 每个分组的标题行本身就是开关，右侧显示当前值 ——
收着也知道「画框：乌木金线」「定时补全：每 12 小时」。折叠状态在会话里记着，
切走再回来还是你留下的样子；提示词和 Chrome 页脚这两块默认收着，不然一开就是一屏文本。
折叠用的是 `grid-template-rows: 1fr → 0fr` 的过渡（Chrome 107+），
所以是滑上去的而不是啪地消失；也因此折叠这一下**不重渲染**，只切一个 class。

**有搜索了。** 抽屉顶上一个框，输进去五页会一起铺开再按文字筛，
每条结果标着它来自哪一页。除了界面上看得见的字，每组还带一串隐藏关键词
（`api key model endpoint`、`cache offline`、`frame`…），
所以中文界面下搜 `api` 也能直接找到接口那一组。搜不到会给一句空状态。

**接口可以存好几套。** `ai.list` 是一个数组，每套 `{id, name, fmt, base, key, model}`，
`ai.cur` 记着选中哪一套。原来那四个平铺字段（`base/key/model/fmt`）保留下来，
但改成**当前那套的只读镜像**——读设置时自动同步。好处是 `ai.js` 里
`configured()`、`endpoint()`、`hasHost()`、请求构造那一整套代码一行都不用改。

这里踩了一脚：`setSettings()` 原来返回的是合并后的对象，切换接口时那份对象里的镜像
还是旧值，界面会闪一下旧地址。改成合并落盘后**再走一遍 `getSettings()`** 返回，
多一次读，但镜像永远是对的。老版本的单份配置会在第一次读设置时自动升成第一档。

**定时与张数带「自定义」。** 定时补全从 `off/6h/daily` 三选一改成**分钟数**
（老值自动换算），下拉里是关闭 / 每小时 / 每 6 小时 / 每 12 小时 / 每天 / 每 3 天 /
自定义…；选自定义就展开「数字 + 单位（分钟/小时/天）」。存回去时按单位换算成分钟，
低于 15 分钟抬到 15（Chrome 的闹钟本来也不适合更密）。重新渲染时反过来
**挑能整除的最大单位**拆回去 —— 120 分钟显示成「2 小时」而不是「120 分钟」。
每轮张数（1–2000）和并发（上限 8）同一套控件。

**顺手修的一个老毛病。** 亚麻卡纸的织纹一直指着 `assets/tex/linen.png`，
可那个文件根本不存在（实际叫 `linen.webp`，而且那是墙面尺度的贴图，
拿来当 64px 的卡纸纹会被 `multiply` 压成灰绿色）。现在换成一张 6px 的内嵌 SVG，
浅浅两道经纬，油画的卡纸终于有了该有的织感，控制台也不再报 404。
这个 404 是这次跑回归时才浮出来的 —— 只有挂着亚麻卡纸的作品才会触发。

**验证**：79 条纯逻辑单测 + 149 条端到端。新增 51 条专门跑设置：
旧配置升级、五页都渲染得出、折叠与记忆、搜索（命中/跨页/英文关键词/空状态/清空）、
多接口（新建/命名/切换/镜像同步/复制/删除）、自定义数值（换算/下限/上限/拆回单位/
闹钟跟着走），外加四条「老设置还能改吗」的兜底。

## 十一之二、v1.12.1 这一版改了什么

**补全的时候看得见在补什么；提示词摊开来，随便改。**

上一版的补全是个黑盒：点下去，等一会儿，只回你一句「已补全 3」。
补了哪几张、哪张失败了、失败在哪一步，全看不到；提示词写死在 `ai.js` 里，
想让它换个说法只能改源码。

**逐张清单**。`applyResult()` 原来返回真假，现在返回**被改动的字段名清单**——
顺手也就有了「这张补了 10 项，那张一项没补」。`runBatch()` 把每张的
`{原名, 新名, 字段清单, 失败原因, 耗时}` 攒成一份报告，边跑边通过 `onProgress`
往面板里送，一行一行长出来，同时进度条按 `i / n` 走。跑完写进 `aistate.report`
（留最近 200 条），关掉设置再打开还在——后台定时补的那些也进同一份清单，
早上打开就知道夜里补了什么。

写这块时把 `applyResult` 里每一处赋值都改成「先比一比再写」，
不然「模型给的值和原值一样」也会被记成一次改动，清单上的数字就虚了。

**提示词摊开**。三份模板（系统 / 名作 / 通用图片）从常量变成带占位符的文本，
可以在设置里直接编辑。占位符替换只认得白名单里那些，写错的原样留着，
一眼能看出没生效。「预览」按当下真实的待补作品渲染，不是编个样例给你看。

一个小设计：编辑框里**始终显示真正在用的那份**——没改过时显示内置原文。
存的时候反过来判断：和内置一字不差就存空串。这样用户「改回默认」和
「手动改成和默认一样」是同一个结果，将来内置文案更新了也能跟着走，
不会被一份早年抄下来的副本钉死。

**安全边界没动。** 词表过滤本来就在 `applyResult()` 里，不在提示词里；
提示词随便改，模型编出来的流派、题材照样过不了白名单。
这一点在测试里单独验了：把整份通用提示词换成一句「MYCUSTOM 看图说话」，
补全照样跑通，返回的野生标签照样被丢掉。

**顺手修的一个脆弱点。** `hexToHsl()` 拿到没有主色或三位简写（`#345`）的作品会整页崩掉——
内置藏品和两个来源都不会产生这种记录，但外来的、手改过的存储会。现在先规整成六位，
认不出就退回默认色。是写测试夹具时被自己绊到才发现的。

**验证**：79 条纯逻辑单测（多了提示词模板替换、改动字段清单）+
98 条端到端（新增 40 条：报告的形状、进度条露出与收起、清单边跑边长、
五绿一红、关掉再开还在、清空、三个编辑框、预览、自定义提示词真的发出去了、
恢复默认存空串、改回一字不差＝当作没改）。

## 十一之二、v1.12.0 这一版改了什么

**接你自己的多模态模型，把「每日新作」和「自定义图库」的空字段补上。**

这两个来源的条目一直是残缺的：Commons 抓回来的没有流派、材质、导览；
本机文件夹扫进来的标题就是文件名。新增 `src/ai.js`，一个 OpenAI / Anthropic
双格式的多模态客户端，加上两套分开写的提示词。完整说明见第五之二节，这里只记要点：

**为什么是两套提示词。** 一开始只写了一套「编目员」提示词，拿本机图片一试就露馅 ——
模型会认真地把一张厨房照片说成「静物画，可能受荷兰黄金时代影响」。所以自定义图库
另起一套：第一句就是「它可能是照片、截图、插画、设计稿、扫描件，也可能是绘画，
先看清楚它到底是什么，别默认它是名画」；标题要求「像相册里给照片起的名字」；
作者一栏**只有画面上真有署名时才填**。

**词表是封闭的。** 流派、地区、题材全部只能从既有词表里挑，模型编的一律丢掉。
不然筛选面板会长出一堆只出现过一次的野生标签。自定义图库额外开了 14 个日常题材
（建筑 / 食物 / 草木 / 天空 / 山峦 / 树林 / 交通工具 / 器物 / 图案 / 文字 /
运动 / 服饰 / 星空 / 机械）和 4 个地区（南亚 / 西亚 / 非洲 / 大洋洲），
内置藏品一个都用不到，只有 AI 认出来时才会出现在筛选里。

**只换机器起的名字。** 判断分两步：先看整个标题是不是「未命名」这类；
再看是不是「相机/截图工具前缀 + 一串数字」—— 前缀后面数字至少四个、字母不超过四个才算。
这样 `IMG_2043`、`Screenshot 2024-01-01 at 12.30.45`、`微信图片_20240101`、
`截屏2024-01-01 下午3.20`、`IMG-20240101-WA0001` 都换掉，而
`Photo of a cat`、`Untitled (Blue)`、`奶奶家的院子` 一个都不碰。
写第一版时用的是一条长正则，`Screenshot 2024-01-01 at 12.30.45` 就漏了
（正则只允许两组数字）；改成「前缀 + 数字字母比例」才稳。

**三处踩过的坑**

- **中文名那一格的启发式误伤了本机图片。** 每日新作常见 `title.zh === title.en`
  （中文名位置塞的还是英文原名），所以写了条规则「两边相同就用模型给的中文名替换」。
  可本机图片的 zh/en 本来就是同一个文件名，这条规则会绕过「标题处理」的设置，
  把 `奶奶家的院子` 换成模型起的名字。现在这条启发式**只对每日新作生效**，
  而且要求原来那格里确实没有汉字。
- **一把读完再写的锁根本不是锁。** 页面和后台各有一份模块实例，
  `chrome.storage` 没有原子比较写，两边同时读到 `lock=0` 就会各跑一轮、
  同一批图片补两遍（花两份钱）。改成**租约**：写上自己的随机记号，
  等 140–340 ms 再读一次，记号还在才算抢到 —— 后写的那个赢，两边读到的是同一个值，
  必然只有一个匹配。长队列每写一次盘续一次租，免得被当成死锁。
  测试里同时发起页面和后台两轮，接口只被打了 2 次。
- **兼容接口的脾气。** 不少 OpenAI 兼容服务不认 `response_format` 或 `temperature`，
  直接 400。现在被 400 / 422 顶回来会自动脱掉这两个字段重发一次。
  模型爱把 JSON 包在 ```json 代码块里、前后再说一句话，也都会剥掉再解析。

**权限是可选的，不用就不问。** manifest 里 `optional_host_permissions` 声明了
`https://*/*` 和 `http://*/*`（本机模型要走 http），但**不是**常驻权限：
只有你填了地址并点「测试连接 / 立即补全 / 去授权」时，浏览器才弹窗问你放行**那一个域名**。
不开这个功能，权限列表和网络行为跟上一版一模一样。

**验证**：56 条纯逻辑单测（端点规整、JSON 剥壳、机器名判断、字段合并的十几种情形）+
47 条端到端（真开浏览器、真走 fetch，接口那头是台假服务器：两种格式、代码块包裹的返回、
400 降级、401 报错、密钥与模型是否传对、图片是不是真的带上了、本机图片走没走通用提示词、
读不到文件时是否留到下次）+ 11 条后台（闹钟周期跟着设置走、消息通道、租约防重）。
另外确认了：**接口留空或开关关掉时，请求数为 0**。

## 十一之二、v1.11.14 这一版改了什么

**瀑布流：进场就是清晰的，不再先糊一会儿。**

上一版把占位图修好之后，空白框没有了，但没取回来的格子会先显示一张模糊的
20px 预览。根子在于取图策略：瀑布流用的是「进视口才取」的懒加载 —— 可
**瀑布流根本不是一条无尽的流，是固定的 72 幅在无限循环**，懒加载在这里没有意义。

- 改成**一次把这 72 幅全取回来**（`fillMasonry`）。取完之后转多少圈都不会再
  出现占位图 —— 循环里的每一格都是取过的。
- 两点讲究：① 同一幅在上下两份副本里各有一个 `<img>`，只发一次请求、两处共用
  （144 个 img 只对应 72 次取图）；② 按离视口的远近排队，`slot()` 是先进先出的，
  所以眼前这一屏最先清晰。
- 失败的多试几次，间隔逐次拉长、封顶 20 秒；离开瀑布流或重新铺过就不再试 ——
  无限循环里一格糊着就会永远糊着。

实测（1920×880，冷启动）：**1 秒时屏内 20/20 全部清晰**（全局 74/144），
3 秒时全局 140/144；此后屏内一直是满的。剩下那 2 幅是本地 mock 缺图返回 404，
与代码无关。

无限循环也顺手验了：周期 == 第二份内容第一格的 `offsetTop`，且那一格与第一格
是同一幅作品 —— 也就是位移绕满一圈后画面逐像素相同；六列的位移始终落在
`[0, 周期)` 内，没有越界。

## 十一之二、v1.11.13 这一版改了什么

**修好「刚进瀑布流时上面一片空白」。** 四处，头一条是病根：

- **占位图挂错了层。** 格子里的 `<img>` 在图取回来之前是 `opacity:0`，
  而那张 20px 的模糊占位图正是以 `background-image` 挂在**这个 img 身上**的 ——
  于是占位图跟着一起被藏了，没加载的格子就是一块纯色 `#141416`。
  占位图挪到 `.mcell` 上（`background:center/cover`），没加载的格子现在是
  一张模糊的预览，图取回来再淡入盖上去。
- **取图不再串行。** 观察回调里原本是 `img.src = await pic(...)`，一 await
  整个循环就串行了 —— 一次只取一张，`pic()` 里那个四路并发的闸门根本用不上。
  改成发出去之后 `.then()`，由 slot() 限流。
- **先取离视口近的。** 一批 entry 是按 DOM 顺序送来的，直接遍历等于
  「第一列整列排在最前」，右边几列的顶格反而等最久。按 `boundingClientRect.top`
  排一下再取，顶上那一屏先满。
- **循环接缝对不齐。** 无缝滚动的周期取的是 `scrollHeight / 2`，但两份内容之间
  还夹着一道 gap，真正的周期是「一份的高 + 一道间距」，少算了半道 ——
  每绕一圈接缝处跳一下。改成取第二份第一格的 `offsetTop`，正好是周期。

另外试过两种「每次进来不一样」的做法，都退回了，记在这儿免得再走一遍：
随机滚动起点 → 第一屏全是没加载的占位图；随机抽 72 幅 → 抽到的几乎都没缓存，
第一屏要糊很久。顺着 A.list 取前 72 幅，正是别的模式已经预取过的那一段，
一进来顶上就有图。

## 十一之二、v1.11.11 这一版改了什么

**修好「只有中间几幅正常、左右都被重叠切割」。** 根因是一个符号错，
在片门附近正好抵消，所以一直藏着：

- `colFrame` 的横轴 `ex` 就是弦的单位向量 `(dx,dy,dz)/w`，它的 z 分量是
  **−cos(pitch)·sin(yaw)**（右侧后退，dz 为负）。
- CSS `rotateY(α)` 把局部 +X 映到 `z' = −sin(α)`，所以要复现这条弦，
  角度必须是 **+yaw**。但 `segAt` 拼出来的是 `rotateY(−yaw)` —— 纵深方向整个镜像了。
- 片门那一段 yaw≈0，`sin(yaw)≈0`，两种写法看不出差别，所以中间几幅一直是对的；
  一往两边拧，画面平面和 canvas 片基就越走越偏：画格飘出带面、彼此重叠、
  被切成条。**canvas 片基和 DOM 画面本来就不是同一套朝向。**
- 同时修掉 `litAt` 的同一处约定：平面法线 `ex × ey = (sin yaw, 0, cos yaw)`，
  对应的也是 `+yaw`，原先按 `−yaw` 算，明暗跟着朝向反了。

另外一处独立的定位误差：

- `.fps` 没有设 `transform-origin`，默认 `50% 50%`。浏览器会把整串变换按原点做共轭
  （`p' = o + M(p − o)`），串里有 `scaleX(k)`，于是额外带出一个与 k 有关的位移。
  片门附近弦≈弧、k≈1 位移为零；一拐弯每片的 k 各不相同，位移就各走各的。
  改成 `transform-origin:0 0` + 绝对像素的 `translate(−cx,−cy)` 之后
  `p' = M(p)`，内容两端严格落在这一段的弦端点上。

实测（1920×880）：相邻两幅在屏幕上的间隙由修前的 **−73…−34px（重叠）**
变成修后的 **+1…+48px（全部为正）**，再没有任何重叠；调试描边下每一幅都
稳稳落在片基的画格里。五种片型、点片门放大、←/→ 键、滚轮、拖拽甩动、
自动步进、三档窗口尺寸全部回归通过。

- **画格白色帧线**：每幅画四周一圈细白边（负片淡暖、幻灯片关掉用自带卡纸边）。
  帧线画在**上层 canvas**上而不是 DOM 切片上——画面切成 72px 薄片，边线画在切片上会在每条接缝
  留一道横线；画在 canvas 上跟着片子弯、跟着走带移动，远端随明暗淡出。
- **焦点图强化**：画格高上限从 0.27×窗高提到 **0.30×（340px 封顶）**；片门段的片基被放映机的光
  「照透」——一圈高斯光池垫在焦点脚下；焦点那幅的压暗再减半，加上正片整体提亮，
  焦点是全条最亮的一格；后退趋势加深，焦点与邻格的尺寸差拉到约 1.3–1.5 倍。

实测：焦点帧所有切片转角与 z 偏差为 0（绝对平整）；五种片型、逐格/连续走带、拖拽甩动、
点片门放大、矮窗口（1366×640）全部通过。

## 十一之二、v1.11.6 这一版改了什么

**胶卷有了多重卷曲与远近节奏。** v1.11.5 的曲线出了片门只卷一个弯，单调地退远。
这一版让整条带子像一卷真拿在手里的片子那样连打几个弯：

- **三条不同周期的波**叠在「平段 → 退远」的底子上：平面卷曲波（±14°，周期约 0.6 格宽）、

- **左右相位错开**：真拿着的胶卷两边不会镜像对称，左侧的弯来得早一点、右侧缓一点。

## 十一之二、v1.11.5 这一版改了什么

**胶卷按真实形态重摆。** v1.11.2–1.11.4 的曲线是「平面内正弦摆＋上下起伏＋绕轴扭转」三波叠加，
加上片门处一个往前顶的高斯鼓包——看着是一条蛇形过山车，而且鼓包比宽幅画格还窄，
**焦点那一幅正好骑在鼓包上被压弯**（实测同一幅画的切片投影高度能差 5%–15%），
自然谈不上「便于欣赏」。这一版把曲线换成真实胶卷唯一的形态：

- **片门平段**：焦点那一幅所在的整段完全水平、零转角、z≡0。焦点图是严格意义上的平面矩形，
  四条边笔直，实测切片高度方差为 0。平段宽度按当前画幅的实际宽度算（宽幅罩得住，窄幅不浪费）。
- **卷曲**：出了平段，yaw 单调地拧向纵深、pitch 让两端上扬——片子正绕过片门两侧看不见的齿轮。
  两条角都用 m²/(1+m²) 饱和曲线，起步处一阶、二阶导都是 0，**平段与弯段之间没有任何棱**。
- **延伸**：透视（焦距 1250）＋平段之外的额外后退，片子在屏幕两端越缩越小、越走越暗，
  消失进放映室深处；焦点与最远可见格的投影大小差约 1.8 倍。
- **焦点更亮**：画格明暗里焦点那一档的压暗系数从 .55 收到 .30（三种片型同步），
  片门正面受光又离得最近，焦点图是全条最亮的一格。
- **画格高上限从 215px 提到 312px**（0.21→0.27 倍窗高），焦点图大到真正「可赏」；
  矮窗口下由原来的整条等比缩进窗口逻辑兜底。
- 绕自身长轴的扭转（ROLL 波）删除：它是齿孔带边缘锯齿的来源，卷曲全部由 yaw＋pitch 表达。

全部实测通过；画法架构（canvas 片身＋薄片画面）不变，性能与 v1.11.4 同级。

## 十一之二、v1.11.4 这一版改了什么

**胶卷有了焦点图。** 片门那一段把片子往前顶起来（一个高斯鼓包，跟着弧长固定在 s=0），
走到片门的那一格离眼睛最近、因此也最大 —— 像片子正从放映机的压片辊上绕过去。

## 十一之二、v1.11.3 这一版改了什么

三件事：胶卷更像真胶片、画面和片基长在一起、不卡了。

### 不卡了：150ms → 16.7ms（满帧）

先量后改。原来片身是三百来个带 3D 变换的 DOM 薄片，走带时中位帧时间 150ms。
挨个试出来的结论有点反直觉：

- 把薄片的背景**全换成纯色**、把齿孔相位**冻死不动** —— 一毫秒都省不下来。
  代价根本不在重绘，而在**元素个数**：几百个 3D 图层，光是每帧合成就吃掉七八帧的时间。
- 于是片身整个搬到 **一张 canvas** 上。几何是不动的，先离屏画一次存起来，
  每帧只 `drawImage` 一次 + 补上几十个跟着走的齿孔；相位量化到 1.2px，
  自动走带时四帧里只有一帧真的重画。
- 顺带发现两处同量级的开销：整屏那层 `mix-blend-mode:overlay` 的胶片颗粒（17ms，
  每帧都要读一次背景再混合）→ 改成在离屏片身上混一次存起来；
  盖在画面之上的**三层**罩子（光束 / 片门光带 / 两侧压暗）→ 并成一层，
  光束直接并进舞台自己的背景。

最后：`film-glide` 16.7ms，和环形长廊、瀑布流一样满帧。

### 画面和片基长在一起

- **画面也切片**。以前每幅画是一整块刚性平面横在弧上，弦和弧对不齐，相邻两幅在屏幕上
  就会互相压住。现在画切成约 72px 一片，每片仍是刚性平面（这么短，弦≈弧，看不出变形），
  整幅画因此贴着片基弯 —— 不变形，也不重叠。
- **接缝要交叠，不能只拉宽**。相邻两片朝向差一点点，边就像扇子一样张开，露出一道楔形的缝；
  横向拉伸补不上（缝是角度差造成的，补齐要拉伸 18%，那画就变形了）。
  正确做法是元素两侧各留一段 pad 让两片实打实地交叠，背景位置跟着挪，几何比例不变；
  最外侧两条边不留，否则画的两头会多出一截没图的黑边。
- **外缘压在画面之上**。片身分两张 canvas：底下一张整条，上面一张只画上下两条外缘。
  上层盖住画面薄片接缝处那点锯齿边 —— 露出来的就是一条干净的帧线，
  实物胶片的画格边本来也是这么来的。

### 更像真胶片

- **片基的明暗按朝向实算**。每一段片身的法线（转过 rotateY→rotateZ→rotateX 之后的 +Z）
  和光照方向做 Lambert + Blinn-Phong，高光就顺着弯道滚过去。片基越亮高光越收着，
  不然幻灯片那种浅卡纸会一片惨白。
- **一条闭合路径一次填完**。一段一段地填会在每个接缝上留一道发丝线（画两次，抗锯齿叠加），
  在深色片基上很显眼。改成整条带子一条路径、颜色用一条沿屏幕横向的渐变，就没有接缝可言。
- 齿孔画成真的四边形（跟着片子的透视走）并带一圈孔口反光；上下两道厚度边一亮一暗；
  片边每个齿距印一小组竖道；再混一层胶片颗粒。电影胶片多一条光学声轨。
- 负片这一档有个坑：滤镜挂在整层上（一个渲染面对七八十个），
  于是「远处压暗」发生在反相**之前** —— 压黑再反相就变成惨白。这一档要反着压：往白压。

### 设置

- 「静止时隐藏界面」的子项 **「详情描述」改名「作品介绍」**（作品名 · 作者 · 收藏地），
  并且真的在四种模式里都生效了 —— 以前只管展墙的 `#label` 和沉浸式的 `#card`，
  环形长廊与胶卷的展签漏掉了。「看点」同样补齐。
- 展签每一行都带一个入场动画（`fill-mode: both`），动画在层叠里压过普通声明，
  所以这几条淡出必须 `!important`，不然勾了也淡不掉。

## 十一之二、v1.11.2 这一版改了什么

**「胶卷是连续的」这条终于做到了。**

刚性整格拼出来的带子做不到连续 —— 每一格是一个平面，相邻两格朝向一变，上下边沿就在接缝处
折断，看着是一排卡片而不是一条片子。全切成薄片又会把画一路挤压变形（v1.10 试过，更糟）。
这一版把两件事拆开：

- **① 片身连续切片**。片基和上下齿孔带切成十几像素宽的薄片，每片按「弧长区间的两个端点」
  摆位 —— 相邻薄片共用端点，所以边沿是顺下来的一条。薄片上没有画，怎么弯都谈不上「变形」。
- **② 画面仍是整块刚性平面**。每幅画一块平板，摆在它那一格的中点上，比片身窄一圈、
  四周露出片基当帧线。画不变形，带子却是连的。

**曲线是波浪＋旋转**：平面内左右摆（正弦，奇函数 → 深度是偶的，两端一样往后退，构图不偏）、
上下起伏（余弦 → 高度是奇的，整条带子成一个斜着的 S）、绕自身长轴扭转，三个周期各不相同。
弧长跟窗口宽走，窗口越宽看见的波越多；波长与深度跟画格等比缩放，小窗口里波形一样好看。

几处必须记下来的坑：

- **齿孔一帧只改一个数**。齿孔画在薄片自己的背景上，每片的相位差是个常数（建好就不动了），
  走带时整条片身只改父层一个 `--pp`。三百多片薄片不用逐个算。
- **画会被拱起的片基戳穿**。一格画是弦，片身是弧，中间差一个矢高。解法是把平板往弧那边
  挪半个矢高（误差两头对半分），再沿**自身法线**抬一点点 —— `translateZ` 必须写在旋转
  **之后**才是沿法线，写在前面是沿世界 Z 轴，不管用。
- **Chrome 的 3D 排序会把片基排到画前面**。两层放在同一个 `preserve-3d` 空间里，
  平面相交时 Chrome 只按整片排序，结果片基一条一条插到画上。解法是让片身与画面
  **各自成一个 3D 空间**（`perspective` 放在两层自己身上，灭点都设在挂点 `0 0`，
  两层严丝合缝），画面就永远整层压在片身之上。
- **薄片切细一点**。相邻薄片的法线略有不同，边沿会留下约 `片高/2 × 转角` 的锯齿。
  在浅色片型（幻灯片）上很显眼，所以薄片宽度从 24px 降到 14px。
- **一格画在弯道上兜不住**。齿孔带与画面之间加了一圈空片基（实物胶片本来就有），
  兼作余量；画面最宽只到 1.85 的长宽比。
- **进胶卷模式时片门那格要对**。以前只铺前 48 幅，从展墙第 60 幅切过来，片子上是第 1 幅，
  而顶栏计数、收藏、放大用的还是第 60 幅。现在窗口罩着当前这幅取。
- 走带没动就整个跳过每帧的摆位计算（定格模式下大部分时间都是静止的）。

## 十一之二、v1.11 这一版改了什么

胶卷模式先按四条毛病重做（见下），再改成**连续多曲**：

- **整条带子一路蛇行**，不是「中间一段平、两头拐」。做法是让**朝向本身**沿弧长做正弦振荡：
  平面内摆动（周期 400）、上下起伏（周期 470）、绕自身长轴扭转（周期 300）——
  三条波周期互不相同，错开之后曲线就不重复了。
- 三个振幅都压在「画还看得清」的范围内：最大偏转约 30°，画面只缩到 87%。
- 再叠一个**整体后退**（按 `(|s|/REACH)^1.6`），两端自然变小、退进黑里，不至于挤成一团。
- 帧间的片基加宽到画格高的 5%，齿孔看得清，一眼就知道这是**一整条**片子而不是一排卡片。

原先那四条毛病的处理：

胶卷模式按你指出的四条重做。之前几版的毛病，根子是**为了「卷」而牺牲了「看画」**：

- **画绝不变形**。v1.10 那版把片子切成薄片，静态截图像实物胶卷，但画是从固定的弯曲带子里
  穿过去的——一路被挤压拉伸，从来没有一刻是平整完整的。现在退回刚性整格，
  每一格自始至终是一个完整的矩形。
- **中间一大段是平的**，转角用 `u⁵` 缓入（起步极慢），所以片门左右四五幅都正对着你、
  都看得清；出了这一段才迅速拧走。
- **不乱**：只画到 2300px 弧长为止，远端干净地淡到 0，不再堆一片压暗虚化的碎片。
- **不晃**：去掉了整条带子的摇摆动画，默认改成**逐格走带**——走一格、停住、再走。
- 接缝用「按弧长区间的两个端点摆位」解决：两端点都落在曲线上，相邻两格严丝合缝；
  弦比弧略短，就把那一格横向压不到 1%（只发生在转角处，画面本身仍是完整矩形）。
- 「斜着盘旋」= 整条带子在世界坐标里转 9°，加上出平段后绕自身长轴的扭转。

## 十一之三、v1.10.0（已回退）

胶卷模式**推翻重做**。前几版都是把「整格画」当刚性矩形摆在曲线上——矩形转过一个角，
接缝处必然裂开，所以怎么调都像一排立着的牌，卷不起来。这一版换了架构：

1. **把片子切成竖直薄片**（每片 30px）。薄片才能贴着任意曲率的曲面，于是带子可以真的弯、真的卷。
2. **曲线是固定的**：每一片的 3D 变换在建带时算一次就不再动。曲线带 `rotateX(roll)`——
   绕自身长轴的扭转，「卷」就是它；再加 yaw（拧向纵深）、pitch（斜着走）和一点起伏。
3. **走带时只有内容在流**：每片每帧只改 `background-position`。这正是放映机的样子——
   片门不动，片子从中间穿过去。既省算力，也天然没有抖动。
4. 画面、齿孔、片基是同一片上的三层背景，所以齿孔严丝合缝地跟着片子走；
   相邻两片互相多盖 4px，盖住 3D 变换各自抗锯齿留下的接缝。
5. 整条带子还会以 46 秒的周期极慢地左右摇一点，像挂着的胶片被气流吹动
   （`prefers-reduced-motion` 下自动关掉）。

## 十一之三、v1.9.1 这一版改了什么

参照实物胶卷的摆法把胶卷模式重做了一遍——之前那版绕在一个正圆筒上，看着和环形长廊是一回事。

- **转角不再均匀**。`a(p) = YAW · f(p/K)`，`f(u)=u³/(1+|u|³)` 在 p=0 处一阶导为 0：
  片门附近那一段几乎是平的、正对着你（画才看得清），出了这一段迅速拧向纵深。
  位置沿弧长积分得到并存表，所以每格间距真实，接缝不会越走越散。
- **蛇形起伏**：整条带子走一条正弦波，画格顺着波的切线倾斜（rotateZ）并轻微扭转（rotateX），
  起伏在片门附近按平方衰减到 0。底下加了一层倒影。
- **相邻两格互相多盖住 26px**：刚性矩形沿曲线转动，转角处必然留下楔形缝，多画一点就盖住了。
- **修掉「屏幕左半边空着」**：片子是首尾相接的环，但格子原来是排成两份线性队列的，
  走到队首左边就没有格子了。现在每格每帧折算到「离片门最近的那一圈」，只需要一份格子，
  两个方向都是无限长的。

## 十一之三、v1.9 这一版改了什么

- **胶卷改成曲面走带**。以前是平铺的一排格子，太规整。现在整条片子绕在一个看不见的大卷筒上：
  θ = 离片门的弧长 / R，`x = R·sinθ`、`z = R·(cosθ−1)`、`rotateY(−θ)` —— 每一格都贴着筒面，
  于是天然有了曲线和远近。再叠一条竖直弧线把两端抬起来，并按切线方向轻微倾斜。
- **齿孔和片基长在每一格自己身上**，片子弯到哪儿它们就跟到哪儿；齿孔用遮罩真「打穿」，
  透出后面放映室的光。（Chrome 把 SVG 遮罩当 alpha 读，白底黑孔是没用的——黑色一样不透明，
  所以孔是用 `fill-rule="evenodd"` 抠出来的。）
- **修掉文字与画面不同步**：以前拿「作品序号」去查「格子坐标」，而格子是复制了两份的，
  走到后半程就整体错位。现在分开记 `fbest`（第几格）与 `fcur`（第几幅）。
- **「静止时隐藏」改成四个勾选项**：界面 / 详情描述 / 看点 / 色条，勾选＝隐藏，默认全勾；
  看点与色条只在沉浸式有。
- **节奏加到秒级 + 分钟级 + 自定义**，默认 15 秒。自定义可填 1 秒 – 60 分钟。

## 十一之三、v1.8 这一版改了什么

- **新增「胶卷」模式**，并把呈现顺序改成 展墙 → 环形长廊 → 胶卷 → 沉浸式 → 瀑布流。
- **展墙墙签补上原名**：中文界面时标题下小字排原文名，英文界面时排中文名。
- **核对了全部中文译名**，改掉 5 处：
  斯塔布斯 *Whistlejacket* 原译「吹哨人」——那是那匹赛马的名字，中文画册通行《枣红马》；
  莫奈 *Water Lilies (Agapanthus)* 原译「龙舌兰」——Agapanthus 是**百子莲**，龙舌兰是 agave；
  沃特豪斯 *The Lady of Shalott* 原译「夏洛特夫人」——诗里是未婚少女，通行《夏洛特姑娘》；
  惠斯勒 *Arrangement in Grey and Black* 原译「协奏曲」——Arrangement 是**排列/编排**，不是 concerto；
  安杰利科 *The Annunciation* 原译「受胎告知」——那是日文说法，中文通行《天使报喜》。
- **环形长廊改成整组居中**：画与展签当成一组在竖直方向居中（略偏下），横幅竖幅都不再一头空一头挤。
- **四种模式都能点开看细节**。顺带修掉一个真 bug：环形长廊为了拖拽设了指针捕获，
  浏览器会把 click 事件改派给整个舞台，挂在每一格上的 `onclick` **从来没触发过**——现在改成按坐标命中判定。
- **轮换设置拆开**：定时轮换只管展墙与沉浸式，环形长廊与胶卷各有自己的节奏可调。
- **「静止时隐藏界面」拆成子项**：界面 / 详情描述与看点 / 色条，可以各自开关。
- **修好今日画夹跳转**：画夹里的作品直接来自 daily 存储，可能是后台刚落地、本页目录还没合并进来的，
  以前取不到就静默 return，看着就是「点了没反应，还停在上一幅」。现在会先重建目录再跳，
  并且切模式时不再拿旧游标先渲染一遍。
